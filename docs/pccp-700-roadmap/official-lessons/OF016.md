# OF016 — Số lớn nhất

- Nguồn đề: [Programmers lesson 42746](https://school.programmers.co.kr/learn/courses/30/lessons/42746?language=javascript)
- Pattern chính: custom comparator trên phép nối
- Mức trong bank: CORE / representative

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Sắp xếp toàn bộ số nguyên không âm theo một thứ tự nào đó, nối biểu diễn của chúng thành một chuỗi và trả chuỗi số lớn nhất có thể. Phải dùng mọi phần tử đúng một lần. Output là string vì kết quả có thể vượt miền Number an toàn.

## 02. Bound

Số phần tử đủ để loại permutation `O(n!)`. Mỗi giá trị có ít chữ số, nên sort `O(n log n)` với comparator so hai chuỗi nối là phù hợp.

Không convert chuỗi kết quả sang Number: JavaScript chỉ biểu diễn chính xác integer đến `Number.MAX_SAFE_INTEGER`.

## 03. Brute force

Sinh mọi permutation, nối từng permutation, rồi lấy chuỗi biểu diễn số lớn nhất. Với `n` phần tử có `n!` thứ tự, tăng quá nhanh.

## 04. Bottleneck

Brute force quyết định thứ tự global, nhưng quan hệ giữa hai phần tử `a`, `b` có thể quyết định cục bộ:

- đặt `a` trước `b` tạo `ab`;
- đặt `b` trước `a` tạo `ba`;
- thứ tự nào có phép nối lớn hơn phải được ưu tiên.

So giá trị riêng của `a` và `b` không đủ: `3 > 30`, nhưng lý do đúng là `330 > 303`.

## 05. Pattern

Đổi mọi số thành string rồi sort bằng:

```text
b+a lớn hơn a+b ⇒ b đứng trước a
```

Trong JavaScript, comparator descending có thể viết `(b+a).localeCompare(a+b)`.

## 06. State

- `ordered`: array string;
- comparator chỉ cần hai candidate `a`, `b`;
- output là `ordered.join('')` sau khi chuẩn hóa case toàn zero.

## 07. Transition

Sort liên tục đặt lại pair theo kết quả so `ab` và `ba`. Sau sort, join toàn bộ string. Nếu phần tử đầu là `"0"`, mọi phần tử đều là zero và output phải là `"0"`, không phải `"000"`.

## 08. Invariant

Trong thứ tự cuối, với mọi cặp adjacent `a`, `b`, ta có `ab >= ba`. Nếu có cặp vi phạm, swap cặp đó làm chuỗi global lớn hơn mà prefix/suffix khác không đổi; vậy thứ tự có vi phạm không thể tối ưu.

Comparator loại mọi adjacent inversion theo tiêu chí trên, nên join cuối đạt maximum.

## 09. Complexity

Gọi `L` là độ dài biểu diễn số:

- map string: `O(nL)`;
- sort: `O(n log n * L)`;
- join: `O(nL)`;
- space: `O(nL)` cho các string và mảng mới.

## 10. Pseudocode

```text
strings = convert every number to string
sort strings so a comes before b when a+b > b+a
if first string is "0": return "0"
return concatenate strings
```

## 11. Code bước 1 — dựng state

```js
function stringifyNumbers(numbers) {
  return numbers.map(String);
}
```

Không dùng arithmetic concatenation vì số chữ số thay đổi và kết quả có thể quá lớn.

## 12. Code bước 2 — viết transition

```js
function concatenationComparator(a, b) {
  return (b + a).localeCompare(a + b);
}
```

Nếu `b+a` từ điển lớn hơn, comparator dương khiến `a` đi sau `b`, đúng thứ tự descending mong muốn.

## 13. Code bước 3 — ghép vòng lặp

```js
function joinLargest(ordered) {
  if (ordered[0] === "0") return "0";
  return ordered.join("");
}
```

Sau comparator, nếu maximum đầu vẫn là `0` thì không có số dương nào.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF016.js](../../../solutions/official/OF016.js).

```js
function largestConcatenatedNumber(numbers) {
  const ordered = [];

  for (const number of numbers) {
    ordered.push(String(number));
  }

  ordered.sort((first, second) => {
    const secondFirst = second + first;
    const firstSecond = first + second;
    return secondFirst.localeCompare(firstSecond);
  });

  if (ordered[0] === "0") {
    return "0";
  }

  return ordered.join("");
}
```

## 15. Dry-run

|---|---|---|

| `34`, `3` | `343 > 334` | `34` trước `3` |

Thứ tự là `34,3,30`, tạo `34330`.

## 16. Edge cases

1. Toàn zero: trả `"0"`.
2. Prefix gần nhau: `12`, `121` ⇒ so `12121` với `12112`.
3. Một phần tử: trả string của nó.
4. Duplicate: comparator trả zero và vẫn phải giữ đủ occurrence.

## 17. Lỗi JavaScript thường gặp

- Numeric sort `(a,b) => b-a`: không tối ưu phép nối.
- Sort theo ký tự đầu: fail khi prefix giống nhau.
- Comparator trả boolean; `.sort()` cần số âm/0/dương.
- Convert kết quả sang Number để xóa zero: có thể mất precision.
- Không xử lý toàn zero, trả chuỗi nhiều số 0.

## 18. Bài transfer cùng pattern

- OF015: numeric comparator và rank, không phải concatenate comparator.
- OF003: lexicographic sort biến prefix global thành adjacent check.
- OF017: sort rồi tìm boundary theo count.

Tín hiệu: chọn thứ tự các token để tối đa hóa chuỗi nối ⇒ comparator phải so hai thứ tự cục bộ `ab` và `ba`.

### Complexity proof from movements

Gọi `L` là độ dài biểu diễn số:

- map string: `O(nL)`;
- sort: `O(n log n * L)`;
- join: `O(nL)`;
- space: `O(nL)` cho các string và mảng mới.

**Proof từ operation của Số lớn nhất:** Tách chi phí chuẩn bị (nếu có sort) khỏi traversal. Trong traversal, mỗi item/candidate được xét đúng số lần mô tả bởi loop; không nhân các loop nối tiếp thành tích. Main loop được mô tả là `sort bằng comparator so second+first với first+second.`; movement là `sort engine gọi comparator; không có pointer thủ công.`. Vì vậy phải cộng chi phí các phase nối tiếp và chỉ nhân khi một phase thật sự chạy trọn bên trong mỗi lượt ngoài. Auxiliary space chính là state `ordered token strings.`, không tính output nếu convention của bài tách output.
