# OF005 — Album hay nhất

- Nguồn đề: [Programmers lesson 42579](https://school.programmers.co.kr/learn/courses/30/lessons/42579?language=javascript)
- Pattern chính: Hash grouping + multi-level sort
- Mức trong bank: TRANSFER / integration

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Chọn tối đa hai bài mỗi genre. Genre có tổng plays lớn hơn xuất trước; trong genre, bài plays lớn hơn trước; hòa plays lấy original index nhỏ hơn. Trả index theo order đó.

## 02. Bound

Group một lần `O(n)`, sort genres và songs `O(n log n)` đủ. Quan trọng là giữ metadata phục vụ ba tầng order.

## 03. Brute force

Mỗi lần chọn bài kế tiếp, scan toàn input tính lại genre totals và candidate; lặp logic grouping.

## 04. Bottleneck

Output order gồm group-level key và item-level key. Cần tách state: `totalByGenre` và list `{index,plays}` theo genre.

## 05. Pattern

Group → aggregate → sort groups → sort items within group → take top 2.

## 06. State

- Map genre→total;
- Map genre→songs;
- ordered genres;
- answer indices.

## 07. Transition

Mỗi input tăng total và push song. Genre comparator total desc. Song comparator plays desc, index asc.

## 08. Invariant

Sau prefix input, totals bằng tổng plays chính xác và lists chứa đủ song kèm original index. Sau xử lý k genre sorted, answer chứa đúng top tối đa hai của k genre đầu theo mọi tie-break.

## 09. Complexity

Time `O(n log n)`, space `O(n)`.

## 10. Pseudocode

```text
group totals and songs
sort genre keys by total descending
for genre:
  sort songs by plays desc then index asc
  append first two indices
return answer
```

## 12. Code bước 2 — viết transition

```js
function compareSongs(a,b) {
  return b.plays-a.plays || a.index-b.index;
}
```

## 13. Code bước 3 — ghép vòng lặp

```js
function topTwo(songs) {
  return [...songs].sort(compareSongs).slice(0,2);
}
```

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF005.js](../../../solutions/official/OF005.js).

```js
function bestAlbumSongIndices(genres, plays) {
  const totalByGenre = new Map();
  const songsByGenre = new Map();

  for (let index = 0; index < genres.length; index++) {
    const genre = genres[index];
    const currentPlays = plays[index];
    const previousTotal = totalByGenre.get(genre) ?? 0;
    totalByGenre.set(genre, previousTotal + currentPlays);

    if (!songsByGenre.has(genre)) {
      songsByGenre.set(genre, []);
    }
    const genreSongs = songsByGenre.get(genre);
    genreSongs.push({ index, plays: currentPlays });
  }

  const orderedGenres = [...totalByGenre.keys()].sort(
    (first, second) => totalByGenre.get(second) - totalByGenre.get(first),
  );
  const answer = [];

  for (const genre of orderedGenres) {
    const genreSongs = songsByGenre.get(genre);
    genreSongs.sort((first, second) => {
      if (first.plays !== second.plays) {
        return second.plays - first.plays;
      }
      return first.index - second.index;
    });

    const selectedCount = Math.min(2, genreSongs.length);
    for (let rank = 0; rank < selectedCount; rank++) {
      answer.push(genreSongs[rank].index);
    }
  }

  return answer;
}
```

## 19. Làm bằng tay trước khi code

Với genre `a` có các bài `(index, plays) = (0,10),(1,10)` và genre `b` có `(2,15)`,
trước hết cộng theo genre: `a:20`, `b:15`, nên xử lý `a` trước. Trong `a`, plays hòa
nên index `0` trước `1`; `b` chỉ có một bài. Kết quả `[0,1,2]`. Ta phải chốt thứ tự group
trước, rồi mới chốt thứ tự item trong từng group.

## 20. Brute force đầy đủ và dry-run

```js
function bestAlbumSongIndicesBrute(genres, plays) {
  const distinctGenres = [...new Set(genres)];

  function totalPlays(targetGenre) {
    let total = 0;
    for (let index = 0; index < genres.length; index++) {
      if (genres[index] === targetGenre) total += plays[index];
    }
    return total;
  }

  distinctGenres.sort((firstGenre, secondGenre) => {
    return totalPlays(secondGenre) - totalPlays(firstGenre);
  });

  const answer = [];
  for (const genre of distinctGenres) {
    const candidateIndices = [];
    for (let index = 0; index < genres.length; index++) {
      if (genres[index] === genre) candidateIndices.push(index);
    }
    candidateIndices.sort((firstIndex, secondIndex) => {
      if (plays[firstIndex] !== plays[secondIndex]) {
        return plays[secondIndex] - plays[firstIndex];
      }
      return firstIndex - secondIndex;
    });
    answer.push(...candidateIndices.slice(0, 2));
  }

  return answer;
}
```

Với ví dụ `a/a/b` ở trên, comparator genre gọi `totalPlays` nhiều lần; rồi mỗi genre lại
quét toàn input để gom bài. Code đúng vì trực tiếp áp cả ba tie-break, nhưng lặp lại aggregate
và grouping. Hai Map tính và lưu chúng đúng một lần trước khi sort.

## 21. Bảng state và init

| State | Kiểu | Lưu chính xác | Init | Vì sao |
| --- | --- | --- | --- | --- |
| `totalByGenre` | `Map<string, number>` | tổng plays của mọi bài trong genre đã đọc | `new Map()` | chưa có aggregate |
| `songsByGenre` | `Map<string, {index,plays}[]>` | record bài và original index theo genre | `new Map()` | chưa có group |
| `orderedGenres` | `string[]` | genre theo total giảm dần | sort keys sau khi group | total phải hoàn tất trước sort |
| `answer` | `number[]` | index đã chốt theo đúng order | `[]` | chưa chọn bài nào |
| `genreSongs` | record array | group đang sort/chọn | lấy từ Map | state riêng mỗi genre |

## 22. Code Blueprint

```text
OUTPUT: mảng original index theo genre rank rồi song rank.
PREPARE: group mỗi song và cộng total của genre trong cùng một scan.
GLOBAL STATE: totalByGenre, songsByGenre, orderedGenres, answer.
INIT: hai Map rỗng; answer rỗng.
MAIN LOOP: scan songs; sort genres; với mỗi genre sort songs và lấy tối đa hai.
CURRENT ITEM: genre/currentPlays khi build; genreSongs khi chọn.
PER-ITERATION STATE: previousTotal; record {index, plays}; selectedCount.
CHECK: group đã có chưa; plays có hòa không; group có dưới hai bài không.
BRANCH: tạo array khi genre mới; comparator dùng index asc khi plays hòa.
UPDATE: cộng total, push record, rồi push selected original index.
POINTER MOVEMENT: index tăng; genre tiếp theo; rank từ 0 đến selectedCount-1.
STOP / RETURN: hết orderedGenres thì return answer.
CLEANUP: không pad genre chỉ có một bài và không lấy bài thứ ba.
```

Map sang code: Contract → ba tầng order; State → hai Map và answer; Transition → cập nhật
đồng bộ total/group; Invariant → hai Map đúng cho prefix; Stop → sau mọi genre trả answer.

## 23. Invariant theo hai phase

- Sau khi xử lý `index` đầu vào, `totalByGenre[g]` là tổng plays của đúng các record genre
  `g` trong prefix, còn `songsByGenre[g]` chứa mỗi record đó đúng một lần với index gốc.
- Trước iteration genre thứ `k`, `answer` chứa tối đa hai bài đúng thứ tự của chính xác
  `k` genre có total lớn nhất đã xử lý. Comparator song bảo toàn plays giảm dần; nhánh hòa
  bảo toàn index tăng dần.

## 24. Ma trận lỗi và revealing test

| Lỗi | Test nhỏ | Kết quả đúng | Vì sao lộ lỗi |
| --- | --- | --- | --- |
| xếp genre theo bài lớn nhất | genres `['a','a','b']`, plays `[6,6,10]` | `[0,1,2]` | total `a=12` lớn hơn `b=10` |
| quên tie index | `['a','a']`, `[10,10]` | `[0,1]` | comparator phải chốt index asc |
| luôn lấy đúng hai | `['a']`, `[5]` | `[0]` | genre có thể chỉ một bài |
| lấy quá hai | `['a','a','a']`, `[3,2,1]` | `[0,1]` | contract giới hạn hai |
| chỉ cập nhật một trong hai Map | `['a','b','a']`, `[4,7,4]` | `[0,2,1]` | aggregate và group bị lệch invariant |
