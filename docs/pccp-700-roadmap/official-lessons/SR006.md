# SR006 — Bán bàn chải đa cấp

- Nguồn đề: [Programmers lesson 77486](https://school.programmers.co.kr/learn/courses/30/lessons/77486?language=javascript)
- Coverage: Tree / Hash / Simulation

## 01. Contract

Mỗi thành viên có đúng một người giới thiệu hoặc root `"-"`. Một chiếc bàn chải tạo 100 tiền. Khi một thành viên nhận một khoản `profit`, họ chuyển lên parent `floor(profit * 10%)` và giữ phần còn lại. Parent tiếp tục áp dụng cùng luật. Với mọi sale, cộng thu nhập thực giữ lại; trả kết quả theo đúng thứ tự `enroll`.

Phần chuyển lên được tính từ khoản vừa nhận ở mỗi tầng, không tính lại từ doanh thu ban đầu.

## 02. Bound

Tối đa 10.000 thành viên và 100.000 sale; depth được giới hạn đủ nhỏ trong đề. Mỗi sale chỉ đi lên parent chain tới root hoặc tới khi commission bằng 0. Number của JavaScript đủ an toàn với miền giá trị đề.

## 03. Brute force

Không cần xây adjacency children rồi DFS toàn cây cho từng sale. Tiền chỉ đi từ seller lên tổ tiên, nên parent pointer là hướng duy nhất cần theo. Quét toàn bộ cây trên mỗi sale sẽ làm công việc không liên quan.

## 04. Bottleneck

Hai chi tiết quyết định:

- Thành viên giữ `profit - floor(profit/10)`, không đơn giản luôn giữ 90% dạng số thực.
- Khi phần chuyển bằng 0, propagation có thể dừng vì mọi ancestor sau cũng nhận 0.

## 05. Pattern

Pattern là **rooted tree parent propagation + hash lookup**. `enroll[i]` có parent `referral[i]`; mỗi event sale trở thành một dòng tiền đi ngược từ node lên root.

## 06. State

- `parent`: `Map<member, referrer>`.
- `earnings`: `Map<member, accumulatedMoney>`.
- `member`: node đang nhận tiền trong một sale.
- `profit`: khoản node hiện tại nhận.
- `commission`: `floor(profit * 0.1)` truyền lên.

## 07. Transition

Tại mỗi node:

1. Tính `commission = floor(profit / 10)`.
2. Cộng `profit - commission` vào earnings của node.
3. Gán `member = parent[member]` và `profit = commission`.
4. Dừng khi tới `"-"` hoặc `profit === 0`.

Lặp transition độc lập cho từng sale rồi cộng dồn.

## 08. Invariant

Trước mỗi iteration trên parent chain, `profit` là chính xác khoản node `member` vừa được child chuyển lên. Sau transition, node đã giữ đúng phần của mình và `commission` là toàn bộ khoản duy nhất còn phải xử lý ở ancestor tiếp theo. Vì mỗi node có một parent, không có nhánh nào bị bỏ sót hay đếm đôi.

`earnings` luôn bằng tổng tiền thực giữ lại từ mọi sale đã xử lý xong cộng với các tầng đã xử lý của sale hiện tại.

## 09. Complexity

Khởi tạo map `O(n)`. Nếu `h` là chiều cao tối đa và có `m` sale, time `O(n + m·h)`; thực tế propagation còn dừng khi tiền về 0. Space `O(n)`.

## 10. Pseudocode

```text
for i in enroll:
  parent[enroll[i]] = referral[i]
  earnings[enroll[i]] = 0
for each sale:
  member = seller
  profit = amount * 100
  while member != root and profit > 0:
    commission = floor(profit / 10)
    earnings[member] += profit - commission
    member = parent[member]
    profit = commission
return enroll.map(member => earnings[member])
```

## 11. Code bước 1 — dựng parent map

```js
const parent = new Map();
const earnings = new Map();
for (let index = 0; index < enroll.length; index++) {
  parent.set(enroll[index], referral[index]);
  earnings.set(enroll[index], 0);
}
```

Map tránh phải tìm index tuyến tính ở mỗi tầng. Không cần danh sách children vì dòng tiền chỉ đi lên.

## 12. Code bước 2 — chia tiền tại một node

```js
const commission = Math.floor(profit * 0.1);
earnings.set(member, earnings.get(member) + profit - commission);
```

Ví dụ node nhận 45: chuyển `floor(4.5)=4`, giữ 41. Dùng `profit * 0.9` sẽ cho số thập phân và sai contract.

## 13. Code bước 3 — leo parent chain

```js
member = parent.get(member);
profit = commission;
```

Đặt trong `while (member !== "-" && profit > 0)`. Điều kiện `profit > 0` là tối ưu hợp lệ: 10% của 0 vẫn là 0 và không ai phía trên có thêm thu nhập.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/SR006.js](../../../solutions/official/SR006.js).

```js
function multiLevelProfits(enroll, referral, seller, amount) {
  const parent = new Map(), earnings = new Map();
  enroll.forEach((member, i) => {
    parent.set(member, referral[i]);
    earnings.set(member, 0);
  });
  for (let sale = 0; sale < seller.length; sale++) {
    let member = seller[sale], profit = amount[sale] * 100;
    while (member !== "-" && profit > 0) {
      const commission = Math.floor(profit * 0.1);
      earnings.set(member, earnings.get(member) + profit - commission);
      member = parent.get(member);
      profit = commission;
    }
  }
  const result = [];
  for (const member of enroll) {
    result.push(earnings.get(member));
  }
  return result;
}
```

## 15. Dry-run

Giả sử `young → edward → mary → root`, young bán 12 chiếc:

| node nhận | profit | chuyển 10% floor | node giữ |
|---|---:|---:|---:|
| young | 1200 | 120 | 1080 |
| edward | 120 | 12 | 108 |
| mary | 12 | 1 | 11 |
| root | 1 | — | không nằm trong kết quả |

Nếu một sale khác làm mary nhận thêm tiền, cộng vào 11; không reset earnings giữa các sale.

## 16. Edge cases

- Seller có parent trực tiếp là root.
- Commission trở thành 0 trước khi tới root.
- Cùng seller xuất hiện nhiều lần: phải cộng dồn.
- Người không bán vẫn có thể nhận commission từ descendant.
- Người không bán và không có descendant sale giữ kết quả 0.
- Kết quả phải theo `enroll`, không theo thứ tự Map hay seller.

## 17. Lỗi JavaScript thường gặp

- Dùng `Math.round` thay `Math.floor`.
- Tính 10% từ doanh thu gốc ở mọi ancestor.
- Gán earnings thay vì cộng dồn.
- Dùng `indexOf` để tìm member ở từng tầng, biến lookup thành tuyến tính.
- Quên nhân `amount` với 100.
- Trả `Array.from(earnings.values())` và ngầm dựa vào insertion order thay vì map theo `enroll` rõ ràng.

## 18. Bài transfer cùng pattern

- OF023: tree relation, nhưng mục tiêu là cắt cạnh/đếm subtree chứ không propagate event.
- DSU/path compression không áp dụng vì parent hierarchy không được phép đổi.
- Các bài cộng aggregate từ node lên tổ tiên: parent map + loop đến root.

Tín hiệu nhận dạng: **mỗi node có một parent và mỗi event chỉ tác động trên đường node→root** ⇒ không DFS toàn cây; leo parent chain và cập nhật tại chỗ.

## 19. Làm bằng tay và brute force executable

Sale 12 chiếc tạo 1.200. Nếu chain là `young → edward → mary → -`, các khoản lần lượt là
`1200 → 120 → 12 → 1`; ba member giữ `1080, 108, 11`. Phải floor lại ở từng tầng.

```js
function multiLevelProfitsBrute(enroll, referral, seller, amount) {
  const earnings = Array(enroll.length).fill(0);

  for (let sale = 0; sale < seller.length; sale += 1) {
    let member = seller[sale];
    let profit = amount[sale] * 100;
    while (member !== "-" && profit > 0) {
      const index = enroll.indexOf(member);
      const commission = Math.floor(profit / 10);
      earnings[index] += profit - commission;
      member = referral[index];
      profit = commission;
    }
  }
  return earnings;
}
```

Brute dùng `indexOf` ở mỗi tầng nên lookup tuyến tính. Bản tối ưu thay quan hệ bằng parent Map.

## 20. Bảng state và khởi tạo

| State | Ý nghĩa | Khởi tạo |
| --- | --- | --- |
| `parent` | member → referrer | ghép `enroll[i]` với `referral[i]` |
| `earnings` | tổng tiền từng member giữ | mỗi member bằng 0 |
| `member` | node đang nhận khoản hiện tại | seller của event |
| `profit` | khoản tới node hiện tại | `amount[sale] * 100` |
| `commission` | khoản truyền đúng một tầng | `floor(profit * 0.1)` |

## 21. Blueprint từ đề đến code

1. Nhận dạng mỗi member có đúng một parent: rooted tree biểu diễn bằng parent pointer.
2. Event chỉ đi từ seller lên ancestor, nên không cần adjacency children hay DFS toàn cây.
3. Dựng Map để lookup parent và earnings `O(1)` trung bình.
4. Ở từng tầng, tính commission từ khoản vừa nhận, cộng phần giữ lại.
5. Dừng tại `"-"` hoặc khi commission đã về 0.
6. Dựng result theo `enroll` để giữ contract thứ tự.

## 22. Invariant, lỗi lộ diện và recall

Trước mỗi vòng while, `profit` là đúng khoản `member` hiện tại vừa nhận từ child. Sau transition,
member giữ `profit-commission` và parent nhận đúng `commission`; tổng tiền được bảo toàn ngoài phần
đi tới root. Earnings không reset giữa sale nên mọi event được cộng dồn.

| Sai lầm | Test làm lộ | Kết quả đúng |
| --- | --- | --- |
| lấy 10% từ doanh thu gốc ở mọi tầng | chain sâu, sale 12 | `1200→120→12→1` |
| dùng round thay floor | profit 19 | truyền 1 |
| quên cộng dồn seller lặp | cùng seller hai sale | tổng hai event |
| trả theo seller/Map traversal | member không bán | vẫn đúng thứ tự enroll |

Recall: **tree event đi lên ⇒ parent Map; mỗi tầng floor từ khoản vừa nhận; cộng dồn rồi trả theo enroll.**
