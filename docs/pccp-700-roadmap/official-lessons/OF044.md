# OF044 — Đá bước

- Nguồn đề: [Programmers lesson 43236](https://school.programmers.co.kr/learn/courses/30/lessons/43236?language=javascript)
- Pattern chính: binary search last feasible + greedy predicate
- Mức trong bank: STRETCH / advanced

## 01. Contract

Giữa start 0 và destination `distance` có rocks. Xóa tối đa n rock để maximize khoảng cách nhỏ nhất giữa các điểm liên tiếp còn lại.

## 02. Bound

Thử subset rock exponential. Answer integer và predicate “đạt minimum gap g được không” đơn điệu; binary search.

## 03. Brute force

Chọn mọi subset xóa, tính min gap, lấy maximum.

## 04. Bottleneck

Với target gap g, scan trái→phải: rock quá gần previous-kept phải xóa. Greedy giữ điểm sớm nhất hợp lệ minimize số removals.

## 05. Pattern

Predicate đếm removals khi `position-previous<g`, gồm destination sentinel. Feasible nếu removals≤n. Tìm last true.

## 06. State

Sorted positions + destination, `previous`, removed; binary low/high/mid.

## 07. Transition

Predicate: gap nhỏ thì remove current; đủ thì keep/update previous. Search feasible mid ⇒ low=mid+1; false ⇒ high=mid; answer low-1.

## 08. Invariant

Greedy previous là điểm kept sớm nhất có thể sau prefix và dùng minimum removals. Predicate true...true,false... theo g. Search interval giữ first false trong `[low,high]`.

## 09. Complexity

Sort `O(R log R)`; predicate `O(R)` × `O(log distance)`; space `O(R)`.

## 10. Pseudocode

```text
sort rocks; append destination
feasible(g): greedily count gaps<g removals
binary search first false g
return g-1
```

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF044.js](../../../solutions/official/OF044.js).

```js
function maximumMinimumRockDistance(distance, rocks, removalsAllowed) {
  const positions = [...rocks].sort((a, b) => a - b);
  positions.push(distance);

  function feasible(minimumGap) {
    let removed = 0;
    let previous = 0;
    for (const position of positions) {
      if (position - previous < minimumGap) {
        removed += 1;
      } else {
        previous = position;
      }
    }
    return removed <= removalsAllowed;
  }

  let low = 0;
  let high = distance + 1;
  while (low < high) {
    const middle = low + Math.floor((high - low) / 2);
    if (feasible(middle)) {
      low = middle + 1;
    } else {
      high = middle;
    }
  }
  return low - 1;
}
```

## 16. Edge cases

Không rock; xóa mọi rock; destination gap phải tính; answer 0/1; rock sát start.

## 17. Lỗi JavaScript thường gặp

## 19. Làm bằng tay và brute force executable

Với `distance=25`, rocks `[2,11,14,17,21]`, xóa tối đa 2 rock:

- target gap 4: xóa 2 và 14, giữ `0 → 11 → 17 → 21 → 25`; feasible;
- target gap 5: greedy buộc xóa ít nhất 3 rock; infeasible.

Vì predicate true tới 4 rồi false từ 5, last feasible là 4. Brute force đúng nghĩa có thể thử
mọi tập rock được giữ:

```js
function maximumMinimumRockDistanceBrute(distance, rocks, removalsAllowed) {
  let best = 0;

  function search(index, kept, removed) {
    if (removed > removalsAllowed) {
      return;
    }
    if (index === rocks.length) {
      const route = [0, ...kept, distance].sort((a, b) => a - b);
      let minimumGap = distance;
      for (let i = 1; i < route.length; i += 1) {
        minimumGap = Math.min(minimumGap, route[i] - route[i - 1]);
      }
      best = Math.max(best, minimumGap);
      return;
    }

    search(index + 1, [...kept, rocks[index]], removed);
    search(index + 1, kept, removed + 1);
  }

  search(0, [], 0);
  return best;
}
```

Brute force có `2^R` nhánh. Bản tối ưu thay việc chọn subset bằng greedy predicate `O(R)`, rồi
binary search trên `gap`.

## 20. Bảng state và khởi tạo

| State | Ý nghĩa | Khởi tạo | Vì sao đúng |
| --- | --- | --- | --- |
| `positions` | rocks đã sort và destination | copy, sort, push `distance` | scan theo thứ tự và không mutate input |
| `previous` | điểm gần nhất được giữ | `0` | start luôn tồn tại |
| `removed` | số điểm đã phải xóa | `0` mỗi predicate | so với budget `removalsAllowed` |
| `low` | gap còn biết là feasible | `0` | gap 0 luôn đạt được |
| `high` | first-false candidate | `distance + 1` | không thể có gap lớn hơn toàn tuyến |

## 21. Blueprint từ đề đến code

1. Nhận dạng cụm “maximize khoảng cách nhỏ nhất” và đặt candidate `minimumGap`.
2. Với candidate cố định, scan trái sang phải và xóa điểm có gap quá nhỏ.
3. Append destination để đoạn cuối tham gia cùng một transition.
4. Chứng minh greedy giữ điểm hợp lệ sớm nhất dùng ít removals nhất trên mỗi prefix.
5. Nhận ra predicate `true → false` khi gap tăng.
6. Binary search first false trong `[0, distance + 1]`, rồi trả `low - 1`.

## 22. Chứng minh, lỗi lộ diện và recall

Khi `position - previous < minimumGap`, giữ cả hai là bất khả thi; xóa `position` giữ
`previous` sớm nhất cho điểm tiếp theo và không dùng nhiều removals hơn lựa chọn khác. Bởi vậy
greedy tính đúng số xóa tối thiểu. Nếu gap `g` feasible thì mọi gap nhỏ hơn cũng feasible, nên
binary search first false và lùi một đơn vị trả đúng last true.

| Sai lầm | Test làm lộ | Kết quả đúng |
| --- | --- | ---: |
| quên destination sentinel | `10, [2,3,7], 1` | 3 |
| khi xóa vẫn cập nhật `previous` | `25, [2,11,14,17,21], 2` | 4 |
| dùng `<`/`<=` sai ở predicate | `10, [5], 0` | 5 |
| không cho phép xóa toàn bộ rock | `10, [2,3,7], 3` | 10 |
| sort trực tiếp làm mutate input | rocks `[17,2,11]` | input giữ nguyên |

Recall: **maximize minimum ⇒ thử một gap; gap thiếu thì xóa current, đủ mới cập nhật previous;
append destination; tìm first false rồi trừ 1.**
