## 01. Contract

`want[i]` là tên sản phẩm và `number[i]` là số lượng cần mua. Khi đăng ký ở một ngày, thành viên nhận ưu đãi trong đúng 10 ngày liên tiếp; `discount[d]` là sản phẩm giảm giá của ngày đó và mỗi ngày mua được một sản phẩm tương ứng.

Đếm bao nhiêu ngày bắt đầu mà cửa sổ 10 ngày cung cấp đủ chính xác nhu cầu. Tổng số lượng cần theo contract là 10, nên nếu mọi sản phẩm cần đều đạt đúng count thì cửa sổ không thể chứa sản phẩm thừa khác.

## 02. Bound

Danh sách discount có thể dài. Dựng lại frequency từ đầu cho mọi cửa sổ tốn `O(10*n)`, vẫn có thể chạy vì 10 cố định, nhưng sliding window cho invariant tổng quát và cập nhật `O(1)` trung bình mỗi ngày.

## 03. Brute force

Với mỗi start, lấy 10 phần tử, dựng Map count rồi so với toàn bộ `want`. Cách này đúng và là baseline tốt để test.

Nó lặp lại việc đếm chín ngày chung giữa hai cửa sổ liên tiếp.

## 04. Bottleneck

Khi cửa sổ dịch một ngày, chỉ hai event xảy ra:

- sản phẩm mới ở bên phải đi vào;
- sản phẩm cũ ở bên trái đi ra.

Không cần đếm lại tám phần tử ở giữa. Ta còn tránh quét mọi category mỗi lần bằng cách giữ số category đang đúng target.

## 05. Pattern

Fixed window độ dài 10:

```text
add current item
if window > 10: remove expired item
if window size == 10 and all required kinds exactly matched: answer++
```

`change(name, delta)` cập nhật cả count và trạng thái matched trước/sau transition.

## 06. State

- `need`: target count theo sản phẩm;
- `windowCount`: count trong cửa sổ hiện tại cho sản phẩm cần;
- `exactlyMatchedKinds`: bao nhiêu key đang có `windowCount === need`;
- `answer`;
- index hiện tại đại diện right boundary.

## 07. Transition

Khi count của `name` đổi bởi `delta`:

1. nếu count cũ bằng target, giảm `exactlyMatchedKinds` vì trạng thái cũ sắp mất;
2. cập nhật count;
3. nếu count mới bằng target, tăng `exactlyMatchedKinds`.

Thứ tự remove-old-match → mutate → add-new-match xử lý đúng cả tăng lẫn giảm.

## 08. Invariant

Sau khi xử lý index `right` và loại index `right-10` nếu có:

- `windowCount` là frequency chính xác của đoạn `max(0,right-9)..right` cho các sản phẩm cần;
- `exactlyMatchedKinds` bằng đúng số key có count hiện tại bằng target;
- khi cửa sổ đủ 10 và matched bằng `need.size`, start `right-9` là ngày đăng ký hợp lệ.

## 09. Complexity

- Dựng need: `O(k)`.
- Mỗi discount vào một lần, ra một lần: `O(n)` Map operations trung bình.
- Space: `O(k)` với `k` sản phẩm cần.

## 10. Pseudocode

```text
need = map(want[i] -> number[i])
windowCount = empty map
matched = 0, answer = 0
define change(name, delta):
    ignore if name not needed
    if old count equals target: matched--
    update count by delta
    if new count equals target: matched++
for right from 0 to discount.length-1:
    change(discount[right], +1)
    if right >= 10: change(discount[right-10], -1)
    if right >= 9 and matched == need.size: answer++
return answer
```

## 12. Code bước 2 — viết transition

```js
function makeCounterTransition(need, windowCount, status) {
  return function change(name, delta) {
    if (!need.has(name)) return;
    const target = need.get(name);
    const before = windowCount.get(name) ?? 0;
    if (before === target) status.matched--;
    const after = before + delta;
    windowCount.set(name, after);
    if (after === target) status.matched++;
  };
}
```

Object `status` chỉ dùng để minh họa mutable shared state; code cuối đóng `exactlyMatchedKinds` trực tiếp trong closure.

## 13. Code bước 3 — ghép vòng lặp

```js
function windowBoundaries(right, size) {
  return {
    entering: right,
    leaving: right >= size ? right - size : -1,
    full: right >= size - 1,
  };
}
```

Với size 10, tại `right = 9` có cửa sổ đầu `0..9`; tại `right = 10`, item index `0` rời.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF052.js](../../../solutions/official/OF052.js).

```js
function discountSignupDays(want, number, discount) {
  const WINDOW_SIZE = 10;
  const need = new Map(want.map((name, index) => [name, number[index]]));
  const windowCount = new Map();
  let exactlyMatchedKinds = 0;
  let answer = 0;

  function change(name, delta) {
    if (!need.has(name)) return;
    const target = need.get(name);
    const before = windowCount.get(name) ?? 0;
    if (before === target) exactlyMatchedKinds--;
    const after = before + delta;
    windowCount.set(name, after);
    if (after === target) exactlyMatchedKinds++;
  }

  for (let right = 0; right < discount.length; right++) {
    change(discount[right], 1);
    if (right >= WINDOW_SIZE) change(discount[right - WINDOW_SIZE], -1);
    if (right >= WINDOW_SIZE - 1 && exactlyMatchedKinds === need.size) answer++;
  }
  return answer;
}
```

## 15. Dry-run

Giả sử cần `apple:2`, cửa sổ đang có `apple:1`:

| Event | Before | matched change | After |
|---|---:|---:|---:|
| apple vào | 1 | sau update đạt target: `+1` | 2 |
| apple khác vào | 2 | trước update rời target: `-1` | 3 |
| apple ra | 3 | sau update trở lại target: `+1` | 2 |

Transition phải kiểm cả trước và sau để matched không bị stale.

## 16. Edge cases

1. Discount ngắn hơn 10: không có ngày hợp lệ.
2. Đúng 10 ngày: chỉ một cửa sổ.
3. Sản phẩm không nằm trong `want`: vẫn chiếm một ngày nhưng không cần lưu count.
4. Một required kind bị thừa: không được tính matched.
5. Item rời và item vào giống nhau: hai transition triệt tiêu đúng.

## 17. Lỗi JavaScript thường gặp

- Off-by-one: remove `right-9` thay vì `right-10`.
- Check cửa sổ trước khi remove item hết hạn.
- Chỉ kiểm `count >= target`; với tổng target bằng 10, exact match diễn đạt invariant rõ hơn.
- Dùng object equality để so hai Map.
- Quên giảm trạng thái matched trước khi thay đổi một count đang đúng target.
- `number` là tên parameter dễ nhầm với `Number`; vẫn hợp lệ nhưng nên đọc rõ ngữ cảnh.

## 18. Bài transfer cùng pattern

- OF053: variable window, left di chuyển theo sum thay vì kích thước cố định.
- OF058: variable window + frequency để cover đủ mọi loại và minimize length.
- OF001: frequency tĩnh; không có transition remove ở left.

Tín hiệu: xét mọi đoạn có cùng độ dài ⇒ fixed window; cửa sổ kế tiếp chỉ add right và remove left.

- **Nhịp lặp:** `for right vì mỗi ngày vào đúng một lần`. Đây là lý do code dùng block bắt đầu bởi `for (let right = 0; right < discount.length; right++) {`, thay vì chọn loop theo thói quen.

#### 19. Làm bằng tay, brute force và Code Blueprint

Đếm frequency của 10 ngày đầu. Khi start tăng một, gạch sản phẩm ngày cũ và thêm sản phẩm
ngày mới; tám/chín ngày giao nhau không cần đếm lại.

```js
function discountSignupDaysBruteForce(want, number, discount) {
  const WINDOW_SIZE = 10;
  let answer = 0;
  for (let start = 0; start + WINDOW_SIZE <= discount.length; start++) {
    const windowCount = new Map();
    for (let offset = 0; offset < WINDOW_SIZE; offset++) {
      const product = discount[start + offset];
      const previousCount = windowCount.get(product) ?? 0;
      windowCount.set(product, previousCount + 1);
    }
    let isValid = true;
    for (let index = 0; index < want.length; index++) {
      const actualCount = windowCount.get(want[index]) ?? 0;
      if (actualCount !== number[index]) {
        isValid = false;
        break;
      }
    }
    if (isValid) answer++;
  }
  return answer;
}
```
