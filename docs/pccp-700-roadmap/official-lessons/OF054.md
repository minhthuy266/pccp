# OF054 — Làm hai queue có tổng bằng nhau

- Nguồn đề: [Programmers lesson 118667](https://school.programmers.co.kr/learn/courses/30/lessons/118667?language=javascript)
- Pattern chính: two queue pointers + conserved sum
- Mức trong bank: TRANSFER / invariant

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Một operation lấy phần tử front của queue này và đưa vào back queue kia. Tìm số operation ít nhất để tổng hai queue bằng nhau; không thể thì `-1`. Các phần tử dương và hai queue ban đầu cùng độ dài.

## 02. Bound

Dùng `shift()` làm mỗi operation `O(n)`. Có thể biểu diễn chuỗi phần tử mà queue1 nhận/mất bằng một window trên `queue1 + queue2`, hai pointer chỉ tiến.

## 03. Brute force

Mô phỏng hai array bằng `shift/push`, thử chuyển từ queue có tổng lớn hơn. Logic choice đúng với số dương nhưng implementation dịch array và cần bound chống cycle.

## 04. Bottleneck

Tổng toàn hệ thống bảo toàn. Nếu total lẻ, impossible. Queue1 tại mọi thời điểm là một đoạn liên tiếp trong chuỗi ghép theo thứ tự chuyển; sum dương cho biết: thấp thì mở right, cao thì tăng left.

## 05. Pattern

Window target `total/2`:

```text
current < target → queue1 nhận combined[right++]
current > target → queue1 bỏ combined[left++]
```

Mỗi pointer tối đa đi qua combined một lần.

## 06. State

- `combined=[...queue1,...queue2]`;
- window queue1 `[left,right)`;
- `current` sum window;
- `target`, `operations`.

## 07. Transition

Nhận phần tử: add trước vị trí right rồi right++. Bỏ phần tử: subtract vị trí left rồi left++. Mỗi transition tương ứng đúng một queue operation.

## 08. Invariant

`current` bằng tổng đoạn `[left,right)` đại diện queue1 sau đúng `operations` moves. Vì value dương, khi current thấp chỉ mở rộng mới có thể tăng; khi cao chỉ thu trái mới có thể giảm. Do đó greedy pointer không bỏ qua target window hợp lệ sớm hơn.

## 09. Complexity

Time `O(n)`, space `O(n)` cho combined. Mỗi pointer bị chặn bởi `2n`; không cần magic loop vô hạn.

## 10. Pseudocode

```text
total=sum both; if odd return -1
target=total/2; combined=q1+q2
left=0; right=len(q1); current=sum(q1); ops=0
while left<combined.length:
  if current==target return ops
  if current<target:
    if right==combined.length: break
    current += combined[right++]
  else: current -= combined[left++]
  ops++
return -1
```

## 11. Code bước 1 — dựng state

```js
function queueWindow(queue1, queue2) {
  return { combined:[...queue1,...queue2], left:0, right:queue1.length };
}
```

## 12. Code bước 2 — viết transition

```js
function receive(state) {
  state.current += state.combined[state.right++];
}
```

## 13. Code bước 3 — ghép vòng lặp

```js
function release(state) {
  state.current -= state.combined[state.left++];
}
```

Hai transition đều tiến pointer, nên không cycle.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF054.js](../../../solutions/official/OF054.js).

```js
function equalQueueSumOperations(queue1, queue2) {
  const total=[...queue1,...queue2].reduce((s,v)=>s+v,0);
  if (total%2) return -1;
  const target=total/2, combined=[...queue1,...queue2];
  let current=queue1.reduce((s,v)=>s+v,0), left=0, right=queue1.length, ops=0;
  while (left<combined.length) {
    if (current===target) return ops;
    if (current<target) {
      if (right>=combined.length) break;
      current += combined[right++];
    } else current -= combined[left++];
    ops++;
  }
  return -1;
}
```

## 15. Dry-run

Q1 sum 14, Q2 sum 16, target 15: current thấp nên nhận front Q2; nếu value làm current cao, bước sau bỏ front Q1. Mỗi thay đổi chính xác một operation và window dịch theo FIFO.

## 16. Edge cases

1. Sum đã bằng: 0.
2. Total lẻ: -1 ngay.
3. Một value lớn hơn target có thể làm impossible.
4. Cần nhiều lần nhận rồi nhiều lần bỏ.

## 17. Lỗi JavaScript thường gặp

- `shift()` lặp.
- Chỉ giới hạn operations bằng số đoán tùy ý.
- Không check total lẻ.
- Pointer right vượt combined.
- Dùng Number nếu constraints tổng vượt safe integer; bài này nằm trong miền Number an toàn theo contract hiện hành.

## 18. Bài transfer cùng pattern

- OF053: positive window đạt target sum trên một sequence.
- OF009: re-enqueue queue item với identity.
- SR004: hai front độc lập nhưng không có invariant sum.

Tín hiệu: move front→back bảo toàn thứ tự vòng và value dương ⇒ biểu diễn queue bằng window trên array nối.
