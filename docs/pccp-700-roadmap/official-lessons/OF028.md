## 01. Contract

Mỗi xuồng chở tối đa hai người và tổng cân nặng không vượt `limit`. Mọi người phải được chở. Trả số xuồng ít nhất.

Không được ghép ba người dù tổng vẫn dưới limit; giới hạn cardinality hai người là phần quan trọng của contract.

## 02. Bound

Thử mọi cách ghép cặp là exponential hoặc ít nhất quadratic. Sort `O(n log n)` rồi hai pointers tuyến tính đủ nhanh cho danh sách lớn.

## 03. Brute force

Chọn một người, thử ghép với mọi người còn lại hoặc đi một mình; backtrack mọi matching và lấy minimum boat. Mỗi quyết định tạo nhiều nhánh tương đương.

## 04. Bottleneck

Người nặng nhất còn lại bắt buộc lên một xuồng ngay trong mọi lời giải. Họ chỉ có hai khả năng:

- ghép được với người nhẹ nhất;
- hoặc không ghép được với bất kỳ ai.

Nếu nặng nhất + nhẹ nhất vượt limit, mọi người khác còn nặng hơn nhẹ nhất nên cũng không ghép được.

## 05. Pattern

Sort tăng dần, giữ `lightest`, `heaviest`. Mỗi vòng đóng một xuồng chứa người nặng nhất:

- nếu ghép được với nhẹ nhất, tiêu thụ cả hai đầu;
- nếu không, tiêu thụ chỉ đầu nặng;
- tăng boat một.

## 06. State

- `sorted` cân nặng tăng dần;
- `lightest`: người nhẹ nhất chưa xử lý;
- `heaviest`: người nặng nhất chưa xử lý;
- `boats`: số xuồng đã đóng.

Vùng chưa xử lý luôn là interval `[lightest, heaviest]`.

## 07. Transition

```text
if lightest == heaviest: one final boat
else if weight[lightest] + weight[heaviest] <= limit:
    lightest++
always:
    heaviest--
    boats++
```

Người nặng nhất luôn rời vùng trong mỗi vòng nên loop kết thúc.

## 08. Invariant

Trước mỗi vòng, mọi người ngoài `[lightest, heaviest]` đã được gán vào đúng `boats` xuồng hợp lệ; chưa ai trong interval được dùng.

Greedy exchange: nếu người nặng nhất ghép được với ai đó, ghép họ với người nhẹ nhất không làm mất giải pháp tốt hơn—partner cũ (nặng hơn hoặc bằng nhẹ nhất) có thể được thay bởi nhẹ nhất, để lại partner cũ linh hoạt hơn. Nếu không ghép được với nhẹ nhất, họ buộc đi một mình.

## 09. Complexity

- Sort: `O(n log n)`.
- Two pointers: `O(n)`; mỗi người bị tiêu thụ một lần.
- Space: `O(n)` vì code copy input trước sort; có thể `O(1)` phụ nếu được mutate input.

## 10. Pseudocode

```text
sort people ascending
left = 0, right = n-1, boats = 0
while left <= right:
    if left == right:
        boats += 1
        break
    if people[left] + people[right] <= limit:
        left += 1
    right -= 1
    boats += 1
return boats
```

## 11. Code bước 1 — dựng state

```js
function sortedWeights(people) {
  return [...people].sort((a, b) => a - b);
}
```

Numeric comparator là bắt buộc; copy tránh làm thay đổi input của caller.

## 12. Code bước 2 — viết transition

```js
function canShare(sorted, lightest, heaviest, limit) {
  return sorted[lightest] + sorted[heaviest] <= limit;
}
```

Chỉ test hai cực trị. Khi pair này fail, không cần thử người ở giữa với heaviest.

## 13. Code bước 3 — ghép vòng lặp

```js
function countBoats(sorted, limit) {
  let left = 0;
  let right = sorted.length - 1;
  let boats = 0;
  while (left <= right) {
    if (left === right) return boats + 1;
    if (canShare(sorted, left, right, limit)) left++;
    right--;
    boats++;
  }
  return boats;
}
```

Không tăng `left` khi người nặng đi một mình; người nhẹ vẫn chưa được xử lý.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF028.js](../../../solutions/official/OF028.js).

```js
function minimumLifeboats(people, limit) {
  const sorted = [...people].sort((a, b) => a - b);
  let lightest = 0;
  let heaviest = sorted.length - 1;
  let boats = 0;
  while (lightest <= heaviest) {
    if (lightest === heaviest) {
      boats++;
      break;
    }
    if (sorted[lightest] + sorted[heaviest] <= limit) lightest++;
    heaviest--;
    boats++;
  }
  return boats;
}
```

## 16. Edge cases

1. Một người: một xuồng.
2. Mọi pair vừa đúng limit.
3. Không pair nào hợp lệ: answer bằng `n`.
4. Duplicate weights.
5. Số người lẻ: cuối cùng `left === right`.

## 17. Lỗi JavaScript thường gặp

- Quên numeric comparator.
- Cho hơn hai người lên xuồng vì chỉ kiểm tổng weight.
- Khi pair fail vẫn tăng `left`, làm mất người nhẹ.
- Đếm boat theo số pair rồi quên người đi một mình.
- Mutate input bằng sort khiến test/caller sau dùng dữ liệu đã đổi.

## 18. Bài transfer cùng pattern

- OF053: cũng có hai pointer nhưng trên window liên tiếp và dựa vào sum positivity.
- OF057: interval greedy chọn endpoint, proof khác exchange pairing.
- OF025: local greedy cần xử lý conflict hàng xóm.

Tín hiệu: mỗi nhóm tối đa hai phần tử + capacity + minimize groups ⇒ sort và quyết định số phận phần tử nặng nhất bằng phần tử nhẹ nhất.

### Loop and condition derivation

- **Nhịp lặp:** `while left <= right`. Đây là lý do code dùng block bắt đầu bởi `while (lightest <= heaviest) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “singleton; nếu không, lightest+heaviest <= limit”. Trong dry run `[70,50,80,50]`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (lightest === heaviest) {`.
- **Tiến triển:** luôn right--. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `boats++` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `boats++;`.
- **Cleanup:** không. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Xuồng cứu sinh:** Boundary inclusive/exclusive và vị trí answer update phải khớp đúng đoạn đang đại diện. Với variable window, chỉ đo answer sau khi validity được phục hồi; với prefix/difference, kiểm tra đúng offset n+1.

#### 19. Làm bằng tay, brute force và Code Blueprint

Sort `[40,50,60,90]`, limit 100. Người 90 chắc chắn cần một xuồng và không ghép được 40.
Người 60 ghép 40; người 50 đi một mình. Mỗi lượt đều chốt số phận người nặng nhất còn lại.

```js
function minimumLifeboatsBruteForce(people, limit) {
  const used = Array(people.length).fill(false);
  let minimumBoats = Infinity;
  function search(boatsUsed) {
    if (boatsUsed >= minimumBoats) return;
    let firstUnused = -1;
    for (let index = 0; index < people.length; index++) {
      if (!used[index]) {
        firstUnused = index;
        break;
      }
    }
    if (firstUnused === -1) {
      minimumBoats = boatsUsed;
      return;
    }
    used[firstUnused] = true;
    search(boatsUsed + 1);
    for (let partner = firstUnused + 1; partner < people.length; partner++) {
      if (used[partner]) continue;
      if (people[firstUnused] + people[partner] > limit) continue;
      used[partner] = true;
      search(boatsUsed + 1);
      used[partner] = false;
    }
    used[firstUnused] = false;
  }
  search(0);
  return minimumBoats;
}
```

Backtracking thử nhiều matching tương đương và tăng theo cấp số mũ. Sau sort, nếu nhẹ nhất
không ghép được nặng nhất thì không ai ghép được; nếu ghép được, dùng nhẹ nhất không làm mất
cơ hội tốt hơn vì mọi người khác đều nặng hơn.

| State | Kiểu | Lưu chính xác gì | Init và lý do | Scope |
| --- | --- | --- | --- | --- |
| `sortedPeople` | number[] | cân nặng tăng | clone rồi numeric sort | toàn hàm |
| `left`,`right` | number | nhẹ/nặng chưa xếp | `0,n-1` | xuyên loop |
| `boats` | number | xuồng đã chốt | `0` | output |

```text
OUTPUT: boats; PREPARE: clone + numeric sort; GLOBAL STATE: left,right,boats
INIT: 0,n-1,0; MAIN LOOP: while left <= right
CURRENT ITEM: lightest và heaviest; PER-ITERATION STATE: không
CHECK: singleton; nếu không, lightest+heaviest <= limit
BRANCH: ghép được thì left++; UPDATE: boats++
POINTER MOVEMENT: luôn right--; STOP / RETURN: interval rỗng, return boats
CLEANUP: không
```

| left/right | Check | Quyết định | State sau | boats |
| --- | --- | --- | --- | ---: |
| 40/90 | 130>100 | 90 đi riêng | right→60 | 1 |
| 40/60 | 100<=100 | ghép | left→50,right→50 | 2 |
| 50/50 | singleton | đi riêng | interval rỗng | 3 |

Invariant đầu vòng: ngoài `[left,right]` đã được xếp hợp lệ trong đúng `boats` xuồng; chưa ai
trong interval được dùng. Sort `O(n log n)`, scan `O(n)`, pointers không lùi; clone `O(n)`.

- Logic: tăng cả hai pointer khi không ghép được; `[40,90]`, limit 100 lộ lỗi.
- Off-by-one: loop `left < right` bỏ singleton.
- Check/update: tăng boats chỉ khi pair, quên người đi riêng.
- Init: sort mặc định lexicographic; `[100,20,3]` lộ lỗi.
- Hidden: đúng bằng limit phải ghép; `[50,50]`, 100.
- Performance: backtracking matching timeout khi n lớn; sort input trực tiếp còn mutate caller.
