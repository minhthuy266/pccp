# SR004 — Hai chồng thẻ

- Nguồn đề: [Programmers lesson 159994](https://school.programmers.co.kr/learn/courses/30/lessons/159994?language=javascript)
- Coverage: Queue / Implementation

## 01. Contract

Có hai chồng thẻ từ, nhưng mỗi chồng chỉ được lấy thẻ ở đầu và không được đổi thứ tự. Với từng từ trong `goal`, ta phải lấy đúng từ đó từ front của một trong hai chồng. Không bắt buộc dùng hết thẻ. Trả `"Yes"` nếu dựng được toàn bộ `goal`, ngược lại trả `"No"`.

## 02. Bound

Mỗi mảng có kích thước nhỏ, nhưng pattern đúng vẫn là mỗi con trỏ chỉ tiến. Đây là cơ hội chuẩn hóa queue bằng head pointer thay vì `shift()`.

## 03. Brute force

Có vẻ mỗi từ có thể chọn một trong hai chồng, nhưng theo contract chỉ front đang lộ mới hợp lệ. Với ràng buộc từ không lặp trong từng chồng của đề, lựa chọn được quyết định trực tiếp; không cần backtracking `2^n`.

## 04. Bottleneck

Không phải kiểm tra từ có “nằm trong” deck hay không. Nó phải nằm **ngay front hiện tại**. Ví dụ deck `['water','drink']` không thể lấy `drink` trước dù `includes('drink')` là true.

## 05. Pattern

Pattern là **merge hai luồng FIFO có thứ tự**. Giữ một head cho mỗi deck, scan `goal` đúng một lần và tiêu thụ head khớp.

## 06. State

- `first`: chỉ số thẻ chưa dùng đầu tiên của `cardDeck1`.
- `second`: chỉ số thẻ chưa dùng đầu tiên của `cardDeck2`.
- `word`: từ hiện tại cần tạo trong `goal`.

Không cần copy hay mutate input.

## 07. Transition

- Nếu `cardDeck1[first] === word`, tăng `first`.
- Nếu không, nhưng `cardDeck2[second] === word`, tăng `second`.
- Nếu cả hai đều không khớp, trả `"No"` ngay.
- Scan hết `goal`, trả `"Yes"`.

## 08. Invariant

Trước mỗi iteration của `goal`, prefix trước `word` đã được dựng hợp lệ; `first` và `second` trỏ đúng front chưa dùng của hai deck. Transition chỉ lấy một front khớp nên giữ nguyên thứ tự trong từng deck. Nếu không front nào khớp, không có thao tác hợp lệ nào có thể tạo từ kế tiếp, vì ta không được bỏ qua thẻ.

## 09. Complexity

Gọi `g = goal.length`: `O(g)` time, `O(1)` auxiliary space. Không dùng `shift()` nên không có chi phí dời phần tử của array.

## 10. Pseudocode

```text
i=0, j=0
for word in goal:
  if cards1[i] == word: i++
  else if cards2[j] == word: j++
  else: return No
return Yes
```

## 11. Code bước 1 — dựng hai queue pointer

```js
let first = 0;
let second = 0;
```

Front hiện tại lần lượt là `cardDeck1[first]` và `cardDeck2[second]`. Khi pointer bằng length, truy cập trả `undefined`, không cần nhánh đặc biệt.

## 12. Code bước 2 — tiêu thụ đúng một front

```js
if (cardDeck1[first] === word) {
  first++;
} else if (cardDeck2[second] === word) {
  second++;
}
```

`else if` thể hiện mỗi từ goal chỉ lấy đúng một thẻ.

## 13. Code bước 3 — fail fast

```js
function hasMatchingFront(cardDeck1, first, cardDeck2, second, word) {
  if (cardDeck1[first] !== word && cardDeck2[second] !== word) {
    return false;
  }
  return true;
}
```

Không nên tiếp tục scan sau mismatch vì trạng thái không thể tự sửa: từ goal hiện tại vẫn chưa được tạo.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/SR004.js](../../../solutions/official/SR004.js).

```js
function canBuildGoal(cardDeck1, cardDeck2, goal) {
  let first = 0, second = 0;
  for (const word of goal) {
    if (cardDeck1[first] === word) first++;
    else if (cardDeck2[second] === word) second++;
    else return "No";
  }
  return "Yes";
}
```

## 15. Dry-run

Deck 1: `i, drink, water`; deck 2: `want, to`; goal: `i, want, to, drink, water`.

| word | front 1 | front 2 | hành động |
|---|---|---|---|
| i | i | want | lấy deck 1 |
| want | drink | want | lấy deck 2 |
| to | drink | to | lấy deck 2 |
| drink | drink | hết | lấy deck 1 |
| water | water | hết | lấy deck 1 |

Scan hết goal ⇒ `Yes`.

## 16. Edge cases

- Dùng hết một deck trước deck còn lại.
- Goal chỉ lấy từ một deck.
- Từ cần có ở sâu trong deck nhưng front khác ⇒ `No`.
- Deck còn thẻ sau khi goal hoàn tất vẫn là `Yes`.
- Mismatch ngay từ từ đầu tiên.

## 17. Lỗi JavaScript thường gặp

- Dùng `includes()` và bỏ qua thứ tự.
- Dùng `shift()` liên tục dù head pointer rõ hơn và không mutate input.
- Yêu cầu dùng hết cả hai deck, trong khi contract không bắt buộc.
- Tăng cả hai pointer hoặc tăng pointer trước khi xác nhận match.
- Trả boolean thay vì chuỗi đúng casing `"Yes"`/`"No"`.

## 18. Bài transfer cùng pattern

- OF009: queue/head pointer, nhưng có event thời gian.
- OF054: hai queue pointer với invariant tổng.
- Merge hai sorted arrays: cũng nhìn hai front, nhưng rule chọn là giá trị nhỏ hơn.

Tín hiệu nhận dạng: **nhiều nguồn giữ nguyên thứ tự nội bộ, chỉ được lấy phần tử đầu** ⇒ một head pointer cho mỗi nguồn.
