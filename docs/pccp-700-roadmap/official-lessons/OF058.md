# OF058 — Mua đá quý

- Nguồn đề: [Programmers lesson 67258](https://school.programmers.co.kr/learn/courses/30/lessons/67258?language=javascript)
- Pattern chính: variable window + frequency Map
- Mức trong bank: TRANSFER / variable window

## 01. Contract

Tìm đoạn liên tiếp ngắn nhất chứa ít nhất một viên của mọi loại xuất hiện trong toàn mảng. Hòa độ dài lấy start nhỏ hơn. Trả vị trí 1-based inclusive.

## 02. Bound

Mọi cặp boundary là `O(n²)`. Hai pointer và Map cho `O(n)` trung bình.

## 03. Brute force

Cho mỗi left mở rộng right đến đủ loại, lặp lại việc đếm đoạn overlap.

## 04. Bottleneck

Window kế chỉ add right/remove left. Khi đủ loại, phải shrink liên tục để tìm window nhỏ nhất kết thúc tại right.

## 05. Pattern

Add current gem; while `countMap.size===requiredKinds`, evaluate candidate rồi remove left.

## 06. State

`left`, `right`, frequency Map, requiredKinds, best boundaries.

## 07. Transition

Entering tăng count. Leaving giảm; count zero phải delete key để Map size đúng. Chỉ update best khi ngắn hơn để giữ tie start sớm.

## 08. Invariant

Map là frequency chính xác của `[left,right]`. Trong while, mọi valid window kết thúc tại right được xét từ dài tới ngắn cho tới khi mất một loại. Best đúng theo `(length,start)` trên prefix right đã xử lý.

## 09. Complexity

Mỗi pointer tiến tối đa n: `O(n)` time, `O(k)` space.

## 10. Pseudocode

```text
required=distinct all gems
for right:
  add gem
  while window covers all:
    update best if shorter
    remove left; left++
return best converted 1-based
```

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF058.js](../../../solutions/official/OF058.js).

```js
function shortestGemShoppingRange(gems) {
  const requiredKinds = new Set(gems).size;
  const windowCount = new Map();
  let left = 0;
  let bestLeft = 0;
  let bestRight = gems.length - 1;

  for (let right = 0; right < gems.length; right++) {
    const enteringGem = gems[right];
    const previousCount = windowCount.get(enteringGem) ?? 0;
    windowCount.set(enteringGem, previousCount + 1);

    while (windowCount.size === requiredKinds) {
      const currentLength = right - left + 1;
      const bestLength = bestRight - bestLeft + 1;
      if (currentLength < bestLength) {
        bestLeft = left;
        bestRight = right;
      }

      const leavingGem = gems[left];
      const remainingCount = windowCount.get(leavingGem) - 1;
      if (remainingCount === 0) {
        windowCount.delete(leavingGem);
      } else {
        windowCount.set(leavingGem, remainingCount);
      }
      left += 1;
    }
  }

  return [bestLeft + 1, bestRight + 1];
}
```

### Loop and condition derivation

- **Nhịp lặp:** `for right thêm gem; while Map đủ loại thì đánh giá và thu trái.`. Đây là lý do code dùng block bắt đầu bởi `for (let right = 0; right < gems.length; right++) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “Map.size === requiredKinds; candidate có ngắn hơn best; remaining có về 0.”. Trong dry run `[0,2]`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (currentLength < bestLength) {`.
- **Tiến triển:** right tăng bởi for; left tăng sau khi xử lý leaving và không lùi.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `tăng count entering; save boundaries; giảm/xóa leaving.` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `for (let right = 0; right < gems.length; right++) {`.
- **Cleanup:** delete key count 0 để Map.size tiếp tục có nghĩa là số loại hiện diện.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

> **Prediction checkpoint — finalization của Mua đá quý:** Dòng `return [bestLeft + 1, bestRight + 1];` chạy per current hay đúng một lần sau khi `for right thêm gem; while Map đủ loại thì đánh giá và thu trái.` kết thúc? Trước return, cleanup `delete key count 0 để Map.size tiếp tục có nghĩa là số loại hiện diện.` và output `đoạn mua ngắn nhất chứa mọi loại gem, trả boundary 1-based.` phải ở trạng thái nào? Return sớm sẽ bỏ state pending nào?

```js
function shortestGemShoppingRange(gems) {
  const requiredKinds = new Set(gems).size;
  const windowCount = new Map();
  let left = 0;
  let bestLeft = 0;
  let bestRight = gems.length - 1;
  for (let right = 0; right < gems.length; right++) {
    const enteringGem = gems[right];
    const previousCount = windowCount.get(enteringGem) ?? 0;
    windowCount.set(enteringGem, previousCount + 1);

    while (windowCount.size === requiredKinds) {
      const currentLength = right - left + 1;
      const bestLength = bestRight - bestLeft + 1;
      if (currentLength < bestLength) {
        bestLeft = left;
        bestRight = right;
      }

      const leavingGem = gems[left];
      const remainingCount = windowCount.get(leavingGem) - 1;
      if (remainingCount === 0) {
        windowCount.delete(leavingGem);
      } else {
        windowCount.set(leavingGem, remainingCount);
      }
      left += 1;
    }
  }
  return [bestLeft + 1, bestRight + 1];
}
```

#### 19. Problem → Code hoàn chỉnh

**Làm tay:** mở right cho tới khi có đủ loại; khi đủ, ghi đoạn rồi bỏ từng gem bên trái trong
khi vẫn đủ. Một right có thể tạo nhiều candidate nên phải `while`. Nếu count leaving về 0, xóa
key; nếu giữ key 0 thì `Map.size` nói dối.

```js
function shortestGemRangeBruteForce(gems) {
  const requiredKinds = new Set(gems).size;
  let bestLeft = 0;
  let bestRight = gems.length - 1;
  for (let left = 0; left < gems.length; left++) {
    const kinds = new Set();
    for (let right = left; right < gems.length; right++) {
      kinds.add(gems[right]);
      if (kinds.size !== requiredKinds) continue;
      if (right - left < bestRight - bestLeft) {
        bestLeft = left;
        bestRight = right;
      }
      break;
    }
  }
  return [bestLeft + 1, bestRight + 1];
}
```

| State | Kiểu | Lưu gì | Init/lý do | Scope |
| --- | --- | --- | --- | --- |
| `windowCount` | Map | frequency chính xác `[left,right]` | empty | xuyên loop |
| `left`,`bestLeft`,`bestRight` | number | biên sống/best | `0,0,n-1` | xuyên loop |
| entering/leaving/count | string/number | event window | từ iteration | iteration |

```text
OUTPUT: pair 1-based; PREPARE: requiredKinds; STATE: Map,left,best; INIT: empty,0,full
LOOP: for right; CURRENT: enteringGem; CHECK: Map.size===requiredKinds
BRANCH: while valid; UPDATE: best nếu ngắn hơn, decrement/delete leaving; POINTER: left++
STOP: hết right; CLEANUP: convert +1; RETURN: pair
```

Invariant: Map đúng window; mỗi valid window kết thúc tại right được xét trước khi remove làm
window invalid. Mỗi gem add/remove tối đa một: `O(n)` expected, Map `O(k)`. Tie chỉ update bằng
`<`, không `<=`.

**Lỗi/test:** Set window không biết duplicate; quên delete zero; dùng `if` bỏ candidate ngắn;
update sau remove bỏ window hiện tại; quên 1-based; `<=` lấy start muộn. Recall:
`add → while covers: save-if-shorter → decrement/delete left → left++ → return best+1`.
