# OF022 — Độ mệt mỏi

- Nguồn đề: [Programmers lesson 87946](https://school.programmers.co.kr/learn/courses/30/lessons/87946?language=javascript)
- Pattern chính: permutation backtracking + pruning
- Mức trong bank: CORE / representative

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Mỗi dungeon `[required, cost]`: chỉ vào được nếu fatigue hiện tại ít nhất `required`, sau đó fatigue giảm `cost`. Mỗi dungeon dùng tối đa một lần; được chọn thứ tự. Tối đa hóa số dungeon hoàn thành.

## 02. Bound

Số dungeon rất nhỏ, cho phép thử các permutation `O(n!)`. Greedy theo required/cost không có rule luôn đúng vì một lựa chọn ảnh hưởng feasibility về sau.

## 03. Brute force

Sinh mọi permutation đủ dài `n`, mô phỏng cho đến dungeon đầu không vào được, lấy max. Nhưng một permutation có dungeon không khả thi ở giữa vẫn có thể bỏ dungeon đó và thử dungeon khác; DFS theo choice hợp lệ tự nhiên hơn.

## 04. Bottleneck

Các order chia sẻ prefix đã chọn và fatigue hiện tại. Backtracking giữ prefix state, chỉ mở rộng dungeon chưa dùng và đủ required; nhánh invalid bị prune ngay.

## 05. Pattern

Choose → explore → unchoose:

```text
for each unused feasible dungeon:
  visited[i]=true
  dfs(fatigue-cost, cleared+1)
  visited[i]=false
```

Cập nhật best ở mọi node vì có thể không còn choice trước khi dùng hết dungeon.

## 06. State

- `fatigue` hiện tại;
- `cleared`;
- `visited[i]` đánh dấu dungeon trong prefix;
- `best` global.

## 07. Transition

Candidate hợp lệ khi `!visited[i] && fatigue >= required`. Mark, recurse với fatigue mới, rồi restore. Vòng for thử mọi dungeon có thể là choice kế tiếp.

## 08. Invariant

Trong `dfs(fatigue,cleared)`, visited chứa đúng `cleared` dungeon của path hiện tại và fatigue là initial trừ tổng cost path đó. Sau unchoose, visited trở lại đúng state trước choice, nên sibling không nhiễm nhau.

## 09. Complexity

- Worst time `O(n!)` (chính xác hơn tổng partial permutations), với n nhỏ.
- Space `O(n)` visited + recursion.
- Feasibility check prune nhiều branch.

## 10. Pseudocode

```text
visited=false; best=0
dfs(fatigue,cleared):
  best=max(best,cleared)
  for each dungeon i:
    if visited or fatigue<required: continue
    visited[i]=true
    dfs(fatigue-cost,cleared+1)
    visited[i]=false
return best
```

## 11. Code bước 1 — dựng state

```js
function createDungeonState(count) {
  return { visited: Array(count).fill(false), best: 0 };
}
```

Visited theo index vì hai dungeon có pair giá trị giống nhau vẫn là hai dungeon riêng.

## 12. Code bước 2 — viết transition

```js
function canEnter(fatigue, dungeon) {
  const [required] = dungeon;
  return fatigue >= required;
}
```

Required chỉ là điều kiện vào; fatigue giảm theo `cost`, không theo required.

## 13. Code bước 3 — ghép vòng lặp

```js
function exploreChoice(visited, index, callback) {
  visited[index] = true;
  callback();
  visited[index] = false;
}
```

Restore phải chạy sau recurse trước khi thử index kế tiếp.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF022.js](../../../solutions/official/OF022.js).

```js
function maximumDungeonCount(initialFatigue, dungeons) {
  const visited = Array(dungeons.length).fill(false);
  let best = 0;

  function dfs(fatigue, cleared) {
    best = Math.max(best, cleared);

    for (let index = 0; index < dungeons.length; index++) {
      const [required, cost] = dungeons[index];
      if (visited[index] || fatigue < required) {
        continue;
      }

      visited[index] = true;
      dfs(fatigue - cost, cleared + 1);
      visited[index] = false;
    }
  }

  dfs(initialFatigue, 0);
  return best;
}
```

## 15. Dry-run

Fatigue 80, dungeons `[80,20],[50,40],[30,10]`: chọn dungeon 0 → fatigue 60; chọn 1 → 20 không vào 2. Backtrack tại 60, thử dungeon 2 trước → fatigue 50, sau đó dungeon 1 vào được; best 3. Đây là lý do order quan trọng.

## 16. Edge cases

1. Không dungeon nào vào được: best 0.
2. Required bằng fatigue: vào được.
3. Greedy cost nhỏ nhất không luôn được giả định đúng.
4. Duplicate dungeon vẫn cần visited theo index.
5. Best đạt ở path ngắn hơn n.

## 17. Lỗi JavaScript thường gặp

- Trừ `required` thay vì `cost`.
- Quên restore visited.
- Return ngay khi một dungeon không khả thi, bỏ các candidate sau.
- Chỉ update best ở depth n.
- Sort/mutate dungeons và tin một greedy chưa chứng minh.

## 18. Bài transfer cùng pattern

- OF036: không cần visited vì choice gắn với index level.
- OF020: permutation có duplicate digit/result và primality check.
- OF041: DFS path dùng edge/ticket đúng một lần và tie lexical.

Tín hiệu: chọn thứ tự các item dùng tối đa một lần, bound n nhỏ, greedy không chắc ⇒ permutation backtracking với restore.

### Loop and condition derivation

- **Nhịp lặp:** `DFS(fatigue, clearedCount); thử mọi dungeon ở mỗi node.`. Đây là lý do code dùng block bắt đầu bởi `function dfs(fatigue, cleared) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “dungeon chưa visited và fatigue >= required.”. Trong dry run `[80,20],[50,40],[30,10]`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (visited[index] \|\| fatigue < required) {`.
- **Tiến triển:** for index quét choices; recursion tăng clearedCount.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `best=max(best,cleared); visited true trước recurse và false sau.` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `function dfs(fatigue, cleared) {`.
- **Cleanup:** restore visited trong đúng branch để sibling thấy state ban đầu.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Độ mệt mỏi:** Base case phải hỏi đúng lúc partial solution đã đủ. Guard candidate chạy trước choose; undo phải đối xứng với choose và nằm sau lời gọi đệ quy trong cùng branch.

### Complexity proof from movements

- Worst time `O(n!)` (chính xác hơn tổng partial permutations), với n nhỏ.
- Space `O(n)` visited + recursion.
- Feasibility check prune nhiều branch.

**Proof từ operation của Độ mệt mỏi:** Mỗi node của cây lựa chọn tương ứng một partial solution thực sự được tạo. Thời gian là số node/nhánh được duyệt nhân chi phí kiểm tra; space là độ sâu recursion cộng state đang chọn. Main loop được mô tả là `DFS(fatigue, clearedCount); thử mọi dungeon ở mỗi node.`; movement là `for index quét choices; recursion tăng clearedCount.`. Vì vậy phải cộng chi phí các phase nối tiếp và chỉ nhân khi một phase thật sự chạy trọn bên trong mỗi lượt ngoài. Auxiliary space chính là state `visited và bestCount.`, không tính output nếu convention của bài tách output.

#### 19. Làm bằng tay và brute force executable

Fatigue 80 với `[[80,20],[50,40],[30,10]]`: order `0→1` dừng ở fatigue 20, nhưng order
`0→2→1` hoàn thành cả ba. Một rule greedy chưa chứng minh có thể bỏ đúng order cần tìm.

```js
function maximumDungeonCountBrute(initialFatigue, dungeons) {
  let best = 0;

  function permute(remaining, order) {
    if (remaining.length === 0) {
      let fatigue = initialFatigue;
      let cleared = 0;
      for (const index of order) {
        const [required, cost] = dungeons[index];
        if (fatigue < required) break;
        fatigue -= cost;
        cleared += 1;
      }
      best = Math.max(best, cleared);
      return;
    }

    for (let index = 0; index < remaining.length; index += 1) {
      const next = remaining.slice();
      const [chosen] = next.splice(index, 1);
      permute(next, [...order, chosen]);
    }
  }

  permute(dungeons.map((_, index) => index), []);
  return best;
}
```
