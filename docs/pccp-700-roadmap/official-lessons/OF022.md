# OF022 — Độ mệt mỏi

- Nguồn đề: [Programmers lesson 87946](https://school.programmers.co.kr/learn/courses/30/lessons/87946?language=javascript)
- Pattern chính: permutation backtracking + pruning
- Mức trong bank: CORE / representative

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Mỗi dungeon `[required, cost]`: chỉ vào được nếu fatigue hiện tại ít nhất `required`, sau đó fatigue giảm `cost`. Mỗi dungeon dùng tối đa một lần; được chọn thứ tự. Tối đa hóa số dungeon hoàn thành.

## 02. Bound

Số dungeon rất nhỏ, cho phép thử các permutation `O(n!)`. Greedy theo required/cost không có rule luôn đúng vì một lựa chọn ảnh hưởng feasibility về sau.

## 03. Brute force

Sinh mọi permutation đủ dài `n`, mô phỏng cho đến dungeon đầu không vào được, lấy max. Nhưng một permutation có dungeon không khả thi ở giữa vẫn có thể bỏ dungeon đó và thử dungeon khác; DFS theo choice hợp lệ tự nhiên hơn.

## 04. Bottleneck

Các order chia sẻ prefix đã chọn và fatigue hiện tại. Backtracking giữ prefix state, chỉ mở rộng dungeon chưa dùng và đủ required; nhánh invalid bị prune ngay.

## 05. Pattern

Choose → explore → unchoose:

```text
for each unused feasible dungeon:
  visited[i]=true
  dfs(fatigue-cost, cleared+1)
  visited[i]=false
```

Cập nhật best ở mọi node vì có thể không còn choice trước khi dùng hết dungeon.

## 06. State

- `fatigue` hiện tại;
- `cleared`;
- `visited[i]` đánh dấu dungeon trong prefix;
- `best` global.

## 07. Transition

Candidate hợp lệ khi `!visited[i] && fatigue >= required`. Mark, recurse với fatigue mới, rồi restore. Vòng for thử mọi dungeon có thể là choice kế tiếp.

## 08. Invariant

Trong `dfs(fatigue,cleared)`, visited chứa đúng `cleared` dungeon của path hiện tại và fatigue là initial trừ tổng cost path đó. Sau unchoose, visited trở lại đúng state trước choice, nên sibling không nhiễm nhau.

## 09. Complexity

- Worst time `O(n!)` (chính xác hơn tổng partial permutations), với n nhỏ.
- Space `O(n)` visited + recursion.
- Feasibility check prune nhiều branch.

## 10. Pseudocode

```text
visited=false; best=0
dfs(fatigue,cleared):
  best=max(best,cleared)
  for each dungeon i:
    if visited or fatigue<required: continue
    visited[i]=true
    dfs(fatigue-cost,cleared+1)
    visited[i]=false
return best
```

## 11. Code bước 1 — dựng state

```js
function createDungeonState(count) {
  return { visited: Array(count).fill(false), best: 0 };
}
```

Visited theo index vì hai dungeon có pair giá trị giống nhau vẫn là hai dungeon riêng.

## 12. Code bước 2 — viết transition

```js
function canEnter(fatigue, dungeon) {
  const [required] = dungeon;
  return fatigue >= required;
}
```

Required chỉ là điều kiện vào; fatigue giảm theo `cost`, không theo required.

## 13. Code bước 3 — ghép vòng lặp

```js
function exploreChoice(visited, index, callback) {
  visited[index] = true;
  callback();
  visited[index] = false;
}
```

Restore phải chạy sau recurse trước khi thử index kế tiếp.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF022.js](../../../solutions/official/OF022.js).

```js
function maximumDungeonCount(initialFatigue, dungeons) {
  const visited = Array(dungeons.length).fill(false);
  let best = 0;
  function dfs(fatigue, cleared) {
    best = Math.max(best, cleared);
    for (let i=0; i<dungeons.length; i++) {
      const [required,cost] = dungeons[i];
      if (visited[i] || fatigue < required) continue;
      visited[i] = true;
      dfs(fatigue-cost, cleared+1);
      visited[i] = false;
    }
  }
  dfs(initialFatigue,0);
  return best;
}
```

## 15. Dry-run

Fatigue 80, dungeons `[80,20],[50,40],[30,10]`: chọn dungeon 0 → fatigue 60; chọn 1 → 20 không vào 2. Backtrack tại 60, thử dungeon 2 trước → fatigue 50, sau đó dungeon 1 vào được; best 3. Đây là lý do order quan trọng.

## 16. Edge cases

1. Không dungeon nào vào được: best 0.
2. Required bằng fatigue: vào được.
3. Greedy cost nhỏ nhất không luôn được giả định đúng.
4. Duplicate dungeon vẫn cần visited theo index.
5. Best đạt ở path ngắn hơn n.

## 17. Lỗi JavaScript thường gặp

- Trừ `required` thay vì `cost`.
- Quên restore visited.
- Return ngay khi một dungeon không khả thi, bỏ các candidate sau.
- Chỉ update best ở depth n.
- Sort/mutate dungeons và tin một greedy chưa chứng minh.
