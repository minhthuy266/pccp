# OF050 — Cuộc đua chạy

- Nguồn đề: [Programmers lesson 178871](https://school.programmers.co.kr/learn/courses/30/lessons/178871?language=javascript)
- Pattern chính: array order + inverse index Map
- Mức trong bank: CORE / implementation

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

`players` là thứ tự hiện tại từ hạng cao đến thấp. Mỗi tên trong `callings` vừa vượt người đứng ngay trước mình, nên hai người đổi chỗ. Áp dụng toàn bộ event theo thứ tự và trả ranking cuối.

Tên người chơi là duy nhất; event hợp lệ nên người được gọi không đứng đầu tại thời điểm đó.

## 02. Bound

Số event có thể rất lớn. Mỗi event dùng `indexOf(calledPlayer)` sẽ quét ranking `O(n)`, tổng `O(n*m)` không phù hợp. Cần lookup vị trí trung bình `O(1)` và swap `O(1)`.

## 03. Brute force

Với mỗi calling, dùng `players.indexOf(name)`, lấy index, rồi swap với index trước. Logic đúng nhưng tìm index lặp lại toàn mảng.

## 04. Bottleneck

Array trả lời tốt câu hỏi “ai ở index i?” nhưng trả lời chậm “player x đang ở index nào?”. Cần lưu đồng thời ánh xạ ngược `player → index`.

Sau swap phải cập nhật cả array và Map; chỉ cập nhật một phía làm hai representation lệch nhau.

## 05. Pattern

Pattern bidirectional representation:

```text
order[index] = player
indexByPlayer[player] = index
```

Event swap hai vị trí adjacent, rồi sửa hai entry Map tương ứng.

## 06. State

- `order`: bản sao mutable của ranking;
- `indexByPlayer`: Map tên → vị trí hiện tại;
- với event: `calledIndex`, `overtakenPlayer`.

## 07. Transition

```text
calledIndex = map[called]
overtaken = order[calledIndex - 1]
order[calledIndex - 1] = called
order[calledIndex] = overtaken
map[called] = calledIndex - 1
map[overtaken] = calledIndex
```

Mỗi event là một adjacent swap nguyên tử.

## 08. Invariant

Trước và sau mỗi calling, với mọi index `i`, `indexByPlayer.get(order[i]) === i`. Array chứa đúng ranking sau prefix event đã xử lý, và Map là inverse chính xác của array.

Transition chỉ đổi hai người; cập nhật đúng bốn ô/entry khôi phục invariant.

## 09. Complexity

- Khởi tạo Map: `O(n)` time/space.
- Mỗi calling: `O(1)` trung bình.
- Tổng: `O(n+m)` time, `O(n)` space.

## 10. Pseudocode

```text
order = copy players
map every player to index
for called in callings:
    i = indexByPlayer[called]
    overtaken = order[i-1]
    swap order[i-1], order[i]
    update index of called and overtaken
return order
```

## 11. Code bước 1 — dựng state

```js
function buildRaceState(players) {
  const order = [...players];
  const indexByPlayer = new Map();

  for (let index = 0; index < order.length; index++) {
    indexByPlayer.set(order[index], index);
  }
  return { order, indexByPlayer };
}
```

Copy array để không mutate input ngoài ý muốn.

## 12. Code bước 2 — viết transition

```js
function applyCalling(order, indexByPlayer, calledPlayer) {
  const calledIndex = indexByPlayer.get(calledPlayer);
  const overtakenPlayer = order[calledIndex - 1];
  order[calledIndex - 1] = calledPlayer;
  order[calledIndex] = overtakenPlayer;
  indexByPlayer.set(calledPlayer, calledIndex - 1);
  indexByPlayer.set(overtakenPlayer, calledIndex);
}
```

Đọc `overtakenPlayer` trước khi ghi đè array.

## 13. Code bước 3 — ghép vòng lặp

```js
function replayCallings(state, callings) {
  for (const calledPlayer of callings) {
    applyCalling(state.order, state.indexByPlayer, calledPlayer);
  }
  return state.order;
}
```

Thứ tự event không được sort hay gom nhóm vì swap sau phụ thuộc ranking do swap trước tạo ra.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF050.js](../../../solutions/official/OF050.js).

```js
function finalRunningOrder(players, callings) {
  const order = [...players];
  const indexByPlayer = new Map(order.map((player, index) => [player, index]));
  for (const calledPlayer of callings) {
    const calledIndex = indexByPlayer.get(calledPlayer);
    const overtakenPlayer = order[calledIndex - 1];
    order[calledIndex - 1] = calledPlayer;
    order[calledIndex] = overtakenPlayer;
    indexByPlayer.set(calledPlayer, calledIndex - 1);
    indexByPlayer.set(overtakenPlayer, calledIndex);
  }
  return order;
}
```

| Event | called index | overtaken | order sau | Map thay đổi |

| `b` | 1 | `a` | `[b,a,c]` | `b→0, a→1` |

## 16. Edge cases

1. Cùng player được gọi nhiều lần liên tiếp.
2. Hai player luân phiên đổi chỗ qua các event.
3. Ranking tối thiểu và một event.
4. Player vừa bị vượt có thể được gọi ở event sau; Map phải mới.

## 17. Lỗi JavaScript thường gặp

- `indexOf` trong mỗi event gây TLE.
- Cập nhật index của called nhưng quên overtaken.
- Đọc overtaken sau khi đã ghi đè `order[i-1]`.
- Sort callings hoặc đếm tần suất, phá event order.
- Mutate trực tiếp `players` rồi tái sử dụng input trong test.

## 18. Bài transfer cùng pattern

- OF005: Map lưu metadata nhóm và index/tie-break phức tạp hơn.
- OF009: queue item phải giữ original index để nhận diện target.
- OF048: parse event thành state chuẩn hóa trước khi so.

Tín hiệu: cần cả lookup theo ID và duy trì order theo index ⇒ giữ array và inverse Map đồng bộ.

### Loop and condition derivation

- **Nhịp lặp:** `replay callings đúng input order.`. Đây là lý do code dùng block bắt đầu bởi `for (const calledPlayer of callings) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “event hợp lệ theo contract; calledIndex > 0.”. Trong dry run `[a,b,c]`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `const order = [...players];`.
- **Tiến triển:** sang calling kế tiếp.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `ghi hai array cell rồi ghi hai Map entry.` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `const indexByPlayer = new Map(order.map((player, index) => [player, index]));`.
- **Cleanup:** không có.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

### Complexity proof from movements

- Khởi tạo Map: `O(n)` time/space.
- Mỗi calling: `O(1)` trung bình.
- Tổng: `O(n+m)` time, `O(n)` space.

**Proof từ operation của Cuộc đua chạy:** Mỗi occurrence được đọc đúng theo vòng sở hữu nó; mỗi lần đọc gây số hữu hạn thao tác Map/Set. Nếu có sort, phần sort chi phối; nếu không, các lượt lookup/update cộng lại theo kích thước input. Main loop được mô tả là `replay callings đúng input order.`; movement là `sang calling kế tiếp.`. Vì vậy phải cộng chi phí các phase nối tiếp và chỉ nhân khi một phase thật sự chạy trọn bên trong mỗi lượt ngoài. Auxiliary space chính là state `order và indexByPlayer phải đồng bộ.`, không tính output nếu convention của bài tách output.

### Additional preserved problem-specific drills and notes

#### 19. Làm bằng tay và brute force đầy đủ

Với order `[a,b,c,d]`, calling `c` nghĩa là tìm `c` ở index 2 rồi đổi với `b`, thành
`[a,c,b,d]`. Calling `c` lần nữa phải tìm trên state mới và cho `[c,a,b,d]`.

```js
function finalRunningOrderBrute(players, callings) {
  const order = [...players];

  for (const calledPlayer of callings) {
    const calledIndex = order.indexOf(calledPlayer);
    const overtakenPlayer = order[calledIndex - 1];
    order[calledIndex - 1] = calledPlayer;
    order[calledIndex] = overtakenPlayer;
  }

  return order;
}
```

Brute đúng vì replay event chính xác nhưng `indexOf` quét `O(n)` mỗi calling. Inverse Map
cache đúng câu hỏi lặp lại “player này đang ở đâu?”, đưa mỗi event về trung bình `O(1)`.

#### 20. Bảng state và init

| State | Kiểu | Lưu chính xác | Init |
| --- | --- | --- | --- |
| `order` | `string[]` | player tại từng rank hiện tại | copy `players` |
| `indexByPlayer` | `Map<string,number>` | rank hiện tại của mỗi player | scan toàn `order` |
| `calledIndex` | `number` | rank trước swap của called player | Map lookup |
| `overtakenPlayer` | `string` | player ngay trước bị vượt | `order[calledIndex-1]` trước mọi write |

#### 21. Code Blueprint

```text
OUTPUT: ranking sau mọi calling, không mutate players.
PREPARE: copy order; dựng inverse Map.
GLOBAL STATE: order và indexByPlayer phải đồng bộ.
INIT: map mỗi order[index] → index.
MAIN LOOP: replay callings đúng input order.
CURRENT ITEM: calledPlayer.
PER-ITERATION STATE: calledIndex, overtakenPlayer.
CHECK: event hợp lệ theo contract; calledIndex > 0.
BRANCH: không có.
UPDATE: ghi hai array cell rồi ghi hai Map entry.
POINTER MOVEMENT: sang calling kế tiếp.
STOP / RETURN: hết event return order.
CLEANUP: không có.
```

Invariant hai chiều: trước/sau mỗi event, `indexByPlayer.get(order[i]) === i` với mọi `i`.
Transition chỉ ảnh hưởng hai người adjacent; bốn update khôi phục đủ hai representation.

#### 22. Ma trận lỗi và recall

| Lỗi | Revealing test | Kết quả đúng |
