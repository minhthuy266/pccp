# OF027 — Tạo số lớn

- Nguồn đề: [Programmers 42883](https://school.programmers.co.kr/learn/courses/30/lessons/42883?language=javascript)
- Pattern: Greedy + monotonic stack
- Mục tiêu: tự đi từ đề → hành động → state → vòng lặp → vị trí block → code

## 1. Đề bài thực sự bắt làm gì?

Cho chuỗi chữ số `number` và số `k`. Xóa đúng `k` chữ số, giữ nguyên thứ tự tương đối của những chữ số còn lại, để tạo số lớn nhất.

Ví dụ:

```text
number = "1924"
k = 2

Các kết quả có thể giữ: 19, 12, 14, 92, 94, 24
Lớn nhất: 94
```

Không được sắp xếp lại chữ số. Từ `1924` không thể tạo `49`, vì `4` vốn đứng sau `9`.

## 2. Từ brute force đến ý tưởng

Cách chậm là thử mọi subsequence dài `number.length - k` rồi lấy số lớn nhất. Số cách chọn tăng rất nhanh.

Khi hai số có cùng độ dài, vị trí khác nhau đầu tiên quyết định số lớn hơn:

```text
949 > 929
```

Chữ số đầu đều là `9`, nhưng chữ số thứ hai `4 > 2`.

Vì vậy:

> Khi chữ số mới lớn hơn chữ số nhỏ đứng ngay trước nó, nếu còn quyền xóa thì xóa chữ số nhỏ để chữ số lớn tiến lên vị trí quan trọng hơn.

## 3. Câu hành động bằng tiếng Việt

Với mỗi chữ số hiện tại:

```text
Lấy current
→ nhìn chữ số cuối đang giữ
→ nếu còn quyền xóa và top < current
→ xóa top
→ giảm số lượt xóa còn lại
→ kiểm tra tiếp top mới
→ khi không thể xóa thêm, push current
```

Sau khi đọc hết chuỗi:

```text
Nếu vẫn còn nợ lượt xóa
→ xóa tiếp từ cuối stack
→ ghép stack thành kết quả
```

## 4. Từ dry run suy ra state

| Thông tin phải sống sang lượt sau | Biến | Ý nghĩa | Giá trị đầu |
|---|---|---|---|
| Các chữ số đang giữ | `stack` | Phần kết quả tốt nhất đang xây | `[]` |
| Còn phải xóa bao nhiêu | `deletionsLeft` | Số lượt xóa chưa sử dụng | `k` |
| Chữ số hiện tại | `currentDigit` | Chữ số đang được xử lý | Lấy từ `number` |

### `deletionsLeft` là gì?

Nếu `k = 2`, ta có hai lượt xóa:

```js
let deletionsLeft = k; // 2
```

Mỗi lần thực sự xóa một chữ số:

```js
stack.pop();
deletionsLeft--;
```

Khi `deletionsLeft === 0`, ta vẫn đọc các chữ số còn lại nhưng không được xóa thêm.

## 5. Dry run: `"1924"`, `k = 2`

Ban đầu:

```text
stack = []
deletionsLeft = 2
```

| Current | Stack trước | Điều kiện thật | Hành động | Stack sau | Còn xóa |
|---|---|---|---|---|---:|
| `1` | `[]` | Stack rỗng | Push `1` | `[1]` | 2 |
| `9` | `[1]` | `1 < 9` | Pop `1`, giảm budget | `[]` | 1 |
| vẫn `9` | `[]` | Stack rỗng | Dừng while, push `9` | `[9]` | 1 |
| `2` | `[9]` | `9 < 2` sai | Push `2` | `[9,2]` | 1 |
| `4` | `[9,2]` | `2 < 4` | Pop `2`, giảm budget | `[9]` | 0 |
| vẫn `4` | `[9]` | Hết quyền xóa | Dừng while, push `4` | `[9,4]` | 0 |

Kết quả:

```text
stack.join("") = "94"
```

## 6. Tại sao `for` có `while` và `push` riêng?

```text
FOR: xử lý mỗi current
├── WHILE: current loại 0, 1 hoặc nhiều chữ số cũ
└── PUSH: giữ current đúng 1 lần
```

- `while` có thể chạy **0, 1 hoặc nhiều lần** cho một current.
- `push(currentDigit)` phải chạy **đúng một lần** cho mỗi current.

Do đó `push` nằm ngoài `while`, nhưng vẫn nằm trong `for`.

### Nếu push nằm trong while: current có thể bị mất

Với `"92"`, khi đọc `9`, stack rỗng nên while không chạy. Nếu push nằm trong while thì `9` không bao giờ được giữ.

### Nếu push nằm trong while: current tự che top cũ

Với:

```text
number = "1239", k = 3
stack trước current 9 = [1,2,3]
```

Nếu pop `3` rồi push `9` ngay:

```text
stack = [1,2,9]
top < current trở thành 9 < 9 → false
```

`9` tự che mất `2` và `1`. Đúng ra phải pop hết `3,2,1`, rồi mới push `9` đúng một lần.

## 7. Tại sao dùng while, không dùng if?

Một current có thể loại nhiều top:

```text
"1239", k = 3

9 loại 3
9 tiếp tục loại 2
9 tiếp tục loại 1
sau đó mới push 9
```

`if` chỉ pop một lần. `while` diễn tả đúng: “chừng nào current còn loại được top và còn quyền xóa thì tiếp tục”.

## 8. Logic tiếng Việt → code

| Logic | Code | Phạm vi |
|---|---|---|
| Tạo nơi giữ chữ số | `const stack = []` | Trước `for` |
| Còn `k` lượt xóa | `let deletionsLeft = k` | Trước `for` |
| Lấy từng chữ số | `for (const currentDigit of number)` | Main loop |
| Còn quyền xóa | `deletionsLeft > 0` | Condition của while |
| Có top để đọc | `stack.length > 0` | Condition của while |
| Top nhỏ hơn current | `stack.at(-1) < currentDigit` | Condition của while |
| Xóa top | `stack.pop()` | Trong while |
| Dùng một lượt xóa | `deletionsLeft--` | Trong while, sau pop |
| Giữ current đúng một lần | `stack.push(currentDigit)` | Sau while, trong for |
| Xóa nợ còn lại | `stack.pop()` | Cleanup sau for |
| Tạo kết quả | `stack.join("")` | Sau cleanup |

## 9. Dựng code tăng dần

Mỗi bước hiển thị toàn bộ function đã dựng tới lúc đó.

### Bước 1 — State

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;
}
```

### Bước 2 — Main for

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;

  // MAIN FOR: chạy một lần cho mỗi current
  for (const currentDigit of number) {
  }
}
```

### Bước 3 — Resolve while

Trước khi xem code, tự trả lời:

- Current được pop top khi nào?
- Vì sao phải check stack không rỗng?
- Vì sao dùng while thay vì if?

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;

  for (const currentDigit of number) {
    // WHILE NẰM TRONG FOR: chạy 0..n lần/current
    while (
      deletionsLeft > 0 &&
      stack.length > 0 &&
      stack.at(-1) < currentDigit
    ) {
    }
  }
}
```

### Bước 4 — Pop và giảm quyền xóa

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;

  for (const currentDigit of number) {
    while (
      deletionsLeft > 0 &&
      stack.length > 0 &&
      stack.at(-1) < currentDigit
    ) {
      stack.pop();
      deletionsLeft--;
    }
  }
}
```

### Bước 5 — Push current đúng một lần

Trước khi xem code:

- While chạy bao nhiêu lần?
- Push current phải chạy bao nhiêu lần?
- Nếu push trong while thì lỗi gì?

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;

  for (const currentDigit of number) {
    while (
      deletionsLeft > 0 &&
      stack.length > 0 &&
      stack.at(-1) < currentDigit
    ) {
      stack.pop();
      deletionsLeft--;
    }

    // Dọn xong mới giữ current đúng một lần
    stack.push(currentDigit);
  }
}
```

### Bước 6 — Cleanup sau for

Với `"4321"`, `k = 2`, không current nào lớn hơn top nên main while không pop. Sau traversal:

```text
stack = [4,3,2,1]
deletionsLeft = 2
```

Ta vẫn nợ hai lượt xóa, nên xóa từ cuối:

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;

  for (const currentDigit of number) {
    while (
      deletionsLeft > 0 &&
      stack.length > 0 &&
      stack.at(-1) < currentDigit
    ) {
      stack.pop();
      deletionsLeft--;
    }

    stack.push(currentDigit);
  }
  // MAIN FOR ĐÃ ĐÓNG

  // CLEANUP CHỈ CHẠY SAU KHI ĐỌC HẾT TƯƠNG LAI
  while (deletionsLeft > 0) {
    stack.pop();
    deletionsLeft--;
  }
}
```

### Bước 7 — Return

```js
function solution(number, k) {
  const stack = [];
  let deletionsLeft = k;

  for (const currentDigit of number) {
    while (
      deletionsLeft > 0 &&
      stack.length > 0 &&
      stack.at(-1) < currentDigit
    ) {
      stack.pop();
      deletionsLeft--;
    }

    stack.push(currentDigit);
  }

  while (deletionsLeft > 0) {
    stack.pop();
    deletionsLeft--;
  }

  return stack.join("");
}
```

## 10. Block nằm ở đâu và vì sao?

| Block | Số lần chạy | Vị trí đúng | Nếu đặt sai |
|---|---:|---|---|
| Tạo state | 1 | Trước for | Trong for sẽ reset lịch sử |
| Resolve while | 0..n/current | Trong for, trước push | Ngoài for không còn current |
| Pop + giảm budget | Mỗi top bị loại | Trong while | Ngoài while sẽ xóa top không thỏa |
| Push current | 1/current | Sau while, trong for | Trong while làm mất current hoặc che top cũ |
| Cleanup | 0..k | Sau for | Trong for kết luận quá sớm |
| Return | 1 | Sau cleanup | Return sớm bỏ input hoặc chưa xóa đủ |

Quy tắc tổng quát:

> Hỏi block chạy 0/nhiều lần, đúng một lần cho mỗi current, hay một lần sau traversal. Câu trả lời quyết định block nằm trong while, trong for hay ngoài for.

## 11. Ví dụ `"19249"`, `k = 2`

```text
1 → [1], còn 2
9 → pop 1, push 9 → [9], còn 1
2 → [9,2], còn 1
4 → pop 2, push 4 → [9,4], còn 0
9 → hết quyền xóa, push 9 → [9,4,9]

Kết quả: 949
```

Nếu giữ lượt xóa để chờ `9` cuối, ta tạo `929`. Vì `949 > 929`, xóa `2` ngay khi gặp `4` là tốt hơn.

Hết quyền xóa không có nghĩa là dừng đọc:

```text
deletionsLeft = 0
→ không được pop thêm
→ vẫn push các chữ số còn lại theo đúng thứ tự
```

## 12. Lỗi thường gặp

1. **Dùng if thay while:** `"1239"`, `k=3` cần current `9` pop ba lần.
2. **Push trong while:** current có thể bị mất hoặc tự che top cũ.
3. **Quên `deletionsLeft--`:** có thể xóa quá `k` chữ số.
4. **Quên cleanup:** `"4321"`, `k=2` phải thành `"43"`.
5. **Dùng `<=` thay `<`:** xóa chữ số bằng nhau không cải thiện prefix.

## 13. Complexity

Code có for chứa while nhưng không phải O(n²):

- Mỗi chữ số được push đúng một lần.
- Một chữ số đã pop thì không quay lại.
- Tổng số lần pop không vượt quá `n`.

```text
Time: O(n)
Space: O(n)
```

## 16. Core cố định và các nút có thể thay đổi

Khi gặp bài mới, không học lại toàn bộ code. Hãy tách:

```text
CORE cố định
→ nút nào của đề đã đổi
→ state/condition/block nào phải đổi theo
```

### Core cố định của Tạo số lớn

```text
Current xuất hiện
→ current có thể loại 0..n top kém hơn
→ loại xong mới push current đúng một lần
```

Khung thường giữ nguyên:

```text
FOR mỗi current:
    WHILE current tốt hơn top theo mục tiêu:
        pop top
        cập nhật budget/state
    PUSH current

SAU FOR:
    finalization theo contract
```

### Ma trận các nút có thể đổi

| Nút đề bài | Bản hiện tại | Có thể đổi thành | Phần code bị ảnh hưởng |
|---|---|---|---|
| Mục tiêu | Số lớn nhất | Số nhỏ nhất | Dấu so sánh trong while |
| Số lượng | Xóa đúng `k` | Xóa nhiều nhất `k` | Cleanup có bắt buộc không |
| Cách mô tả | Xóa `k` | Giữ đúng `m` | Budget/độ dài output |
| Output | Chuỗi chữ số | Index bị xóa/được giữ | Stack lưu digit hay index/object |
| Equality | Giữ digit bằng nhau | Ưu tiên index sớm/muộn | Strict/non-strict |
| Dữ liệu | Chữ số | Ký tự, điểm, hạng | Comparator |
| Finalization | Pop phần đuôi còn nợ | Dừng khi đủ `m` | Block sau for |

## 17. Các biến thể gần

### Biến thể 1 — Tạo số nhỏ nhất

Core và block scope giữ nguyên. Chỉ định nghĩa “current tốt hơn top” đổi:

```js
// Lớn nhất
stack.at(-1) < currentDigit

// Nhỏ nhất
stack.at(-1) > currentDigit
```

Muốn lớn thì chữ số lớn tiến lên trước; muốn nhỏ thì chữ số nhỏ tiến lên trước. Cần đọc thêm contract về số `0`: kết quả có được bắt đầu bằng `0` hay không.

### Biến thể 2 — Giữ đúng `m` chữ số

Đề có thể nói:

```text
Chọn đúng m chữ số, giữ nguyên thứ tự, tạo số lớn nhất.
```

Đây vẫn là cùng lõi vì:

```js
const k = number.length - m;
```

Dấu hiệu quan trọng là output vẫn là subsequence giữ nguyên thứ tự.

### Biến thể 3 — Xóa nhiều nhất `k`

Contract này khác “xóa đúng `k`”. Nếu không bắt dùng hết budget, cleanup không được tự động pop hết phần còn lại.

| Contract | Cleanup |
|---|---|
| Xóa đúng `k` | Bắt buộc dùng hết budget |
| Xóa nhiều nhất `k` | Không mặc định dùng hết |

### Biến thể 4 — Trả index thay vì chuỗi

Nếu output cần vị trí, stack phải lưu đủ thông tin:

```js
stack.push({
  digit: currentDigit,
  index
});
```

Condition đọc `stack.at(-1).digit`. Core không đổi nhưng representation của state đổi theo output.

### Biến thể 5 — Dữ liệu không phải chữ số

Câu chuyện có thể dùng ký tự, điểm, thứ hạng hoặc độ ưu tiên. Nếu vẫn là:

```text
Loại một số phần tử
→ giữ nguyên thứ tự
→ tạo subsequence lớn nhất/nhỏ nhất theo comparator
```

thì vẫn có thể nghĩ tới core monotonic stack này.

## 18. Biến thể kết hợp kiểu PCCP

Ví dụ:

> Cho mảng điểm. Giữ đúng `m` phần tử theo thứ tự ban đầu để tạo dãy lớn nhất theo thứ tự từ điển. Nếu hai dãy giá trị bằng nhau, ưu tiên dãy dùng index sớm hơn.

| Câu hỏi | Phân tích |
|---|---|
| Core đổi không? | Current vẫn có thể loại top kém hơn |
| Budget là gì? | `k = n - m` |
| Stack lưu gì? | Cả value và index |
| Equality có pop không? | Theo tie-break index |
| Cleanup có cần không? | Có, vì phải giữ đúng `m` |

Nếu value bằng nhau và đề ưu tiên index sớm, ta giữ phần tử cũ, không pop khi bằng nhau:

```js
stack.at(-1).value < currentValue
```

## 19. Bài nhìn giống nhưng core này không đủ

### Cho phép sắp xếp lại

Nếu được đổi thứ tự, đây không còn là bài subsequence; có thể chỉ cần sort hoặc counting.

### Bắt buộc xóa một đoạn liên tiếp

Không được pop các vị trí rời rạc. Có thể cần sliding window hoặc ghép prefix/suffix.

### Mỗi vị trí có chi phí xóa khác nhau

Nếu xóa vị trí `i` tốn `cost[i]` và tổng chi phí bị giới hạn, pop top nhỏ hơn không tự động tối ưu; có thể cần DP.

### Có nhiều query

Nếu cùng một chuỗi có rất nhiều truy vấn `k`, chạy lại O(n) cho mỗi query có thể không đủ; phải phân tích lại bounds.

Quy tắc chống dùng template máy móc:

> Chỉ dùng core này khi được bỏ các phần tử rời rạc, phải giữ thứ tự tương đối, và quyết định local “current tốt hơn top” có thể được chứng minh không làm mất lời giải tối ưu.
