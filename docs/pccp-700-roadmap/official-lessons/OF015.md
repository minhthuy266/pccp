# OF015 — Số thứ K

- Nguồn đề: [Programmers lesson 42748](https://school.programmers.co.kr/learn/courses/30/lessons/42748?language=javascript)
- Pattern chính: slice → numeric sort → rank
- Mức trong bank: CORE / warmup

Tài liệu này diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Input gồm mảng số `array` và nhiều command `[i, j, k]`. Với từng command:

1. lấy đoạn từ vị trí `i` đến `j`, tính cả hai đầu;
2. sắp đoạn đó tăng dần;
3. lấy phần tử ở vị trí thứ `k` trong đoạn đã sort.

Output là một mảng, mỗi phần tử ứng với một command và phải giữ nguyên thứ tự command.

Điểm dễ sai: đề đánh số vị trí từ `1`, JavaScript đánh index từ `0`.

## 02. Bound

Theo constraint của bài official, dữ liệu nhỏ: mảng và số command đều đủ nhỏ để tạo một subarray rồi sort riêng cho từng command. Không cần prefix structure hay selection algorithm.

Nếu `n = array.length`, `q = commands.length`, độ dài đoạn lớn nhất là `n`, ngân sách `O(q * n log n)` an toàn.

## 03. Brute force

Với mỗi command, duyệt toàn bộ `array`, tự chép các phần tử có vị trí nằm trong `[i, j]`, sort rồi đếm đến phần tử thứ `k`.

Cách này đúng. Thậm chí với bound của bài, đây đã gần lời giải cần dùng.

## 04. Bottleneck

Bottleneck không phải hiệu năng mà là biến đổi chỉ số và comparator:

- `i` 1-based phải thành `i - 1`;
- `slice(start, end)` lấy `start` nhưng bỏ `end`, nên đầu phải là `i - 1`, cuối là `j`;
- `.sort()` mặc định của JavaScript so chuỗi, khiến `[10, 2, 1]` thành `[1, 10, 2]`.

## 05. Pattern

Pattern là pipeline độc lập cho từng query:

```text
command → slice đúng interval → numeric sort → lấy rank → append answer
```

Không cần giữ state xuyên qua các command ngoài mảng kết quả.

## 06. State

State tối thiểu của một command:

- `start`, `end`, `rank`;
- `sorted`: bản sao của đúng đoạn cần xét;
- giá trị trả về `sorted[rank - 1]`.

## 07. Transition

Mỗi command chuyển thành đúng một output:

```text
[start, end, rank]
→ array.slice(start - 1, end)
→ sort((a, b) => a - b)
→ [rank - 1]
```

Các transition không làm thay đổi `array` gốc vì `slice()` trả mảng mới.

## 08. Invariant

Sau khi xử lý `t` command đầu tiên, `answer` chứa đúng `t` kết quả, đúng thứ tự, và mỗi kết quả là phần tử rank `k` của đoạn đóng `[i, j]` sau numeric sort.

Trong callback của một command, sau `slice` thì `sorted` chứa đúng các phần tử ở index `i-1..j-1`; sau `sort` chúng tăng dần.

## 09. Complexity

Gọi `m` là độ dài đoạn của một command:

- time cho command đó: `O(m log m)`;
- space: `O(m)` cho bản sao;
- toàn bài: `O(Σ m log m)`, chặn trên bởi `O(q * n log n)`.

## 10. Pseudocode

```text
answer = empty array
for each [start, end, rank] in commands:
    part = copy array from start-1 through end-1
    sort part ascending numerically
    append part[rank-1] to answer
return answer
```

## 11. Code bước 1 — dựng state

Trước tiên chỉ destructure command và tạo subarray đúng:

```js
function kthNumbersStep1(array, commands) {
  return commands.map(([start, end, rank]) => {
    const part = array.slice(start - 1, end);
    return { part, rank };
  });
}
```

Nếu command là `[2, 5, 3]`, `slice(1, 5)` lấy index `1,2,3,4`, tức vị trí `2..5` theo đề.

## 12. Code bước 2 — viết transition

Thêm numeric comparator và đổi rank về index:

```js
function solveOneCommand(array, [start, end, rank]) {
  const sorted = array.slice(start - 1, end).sort((a, b) => a - b);
  return sorted[rank - 1];
}
```

Comparator âm khi `a < b`, dương khi `a > b`, nên sort tăng dần theo số.

## 13. Code bước 3 — ghép vòng lặp

Mỗi command độc lập nên dùng `map` đúng nghĩa “một input → một output”:

```js
function kthNumbersStep3(array, commands) {
  return commands.map((command) => solveOneCommand(array, command));
}
```

Không dùng `forEach` rồi quên `push`, và không sort trực tiếp `array` gốc.

## 14. Code hoàn chỉnh

Code executable nằm tại [solutions/official/OF015.js](../../../solutions/official/OF015.js).

```js
function kthNumbers(array, commands) {
  const answer = [];

  for (const [start, end, rank] of commands) {
    const sorted = array.slice(start - 1, end).sort((a, b) => a - b);
    answer.push(sorted[rank - 1]);
  }

  return answer;
}
```

## 15. Dry-run

Với `array = [1,5,2,6,3,7,4]`, command `[2,5,3]`:

| Bước | Giá trị |
|---|---|
| Đổi start | `2 - 1 = 1` |
| Slice | `array.slice(1,5) = [5,2,6,3]` |
| Numeric sort | `[2,3,5,6]` |
| Đổi rank | `3 - 1 = 2` |
| Kết quả | `sorted[2] = 5` |

## 16. Edge cases

1. Đoạn chỉ có một phần tử: `[i, i, 1]`.
2. Lấy toàn bộ mảng: `[1, n, k]`.
3. Có số nhiều chữ số: phải chứng minh đã dùng numeric comparator.
4. Nhiều command trùng nhau: vẫn trả đủ kết quả theo thứ tự.

## 17. Lỗi JavaScript thường gặp

- `slice(start - 1, end - 1)`: mất phần tử tại `end`.
- `sorted[k]`: lệch một vì `k` là rank 1-based.
- `.sort()` không comparator: sort theo biểu diễn chuỗi.
- `.splice()`: mutate mảng gốc và làm command sau sai.
- sort `array` trước khi slice: phá interval theo thứ tự ban đầu.

## 18. Bài transfer cùng pattern

- OF016: comparator không còn là `a - b`, mà so hai phép nối chuỗi.
- OF017: sort xong phải tìm boundary thỏa một điều kiện, không lấy rank trực tiếp.
- SR001: luyện nested index và shape trước khi chuyển sang matrix simulation.

Khi tự học, đóng phần code và viết lại `slice(start - 1, end)`, comparator, `rank - 1` từ trí nhớ.

### Loop and condition derivation

- **Nhịp lặp:** `quét từng [start,end,rank] trong commands.`. Đây là lý do code dùng block bắt đầu bởi `for (const [start, end, rank] of commands) {`, thay vì chọn loop theo thói quen.
- **Điều kiện của nhịp:** Blueprint nói “contract bảo đảm rank hợp lệ trong đoạn; không cần branch.”, nên current không cần một nhánh true/false riêng. Loop `for (const [start, end, rank] of commands) {` tự xác định current nào được đọc; thêm `if` sẽ tạo một quyết định không có trong contract.
- **Tiến triển:** for...of tự sang command kế; slice dùng end exclusive.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `answer.push(sortedSection[rank - 1]).` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `for (const [start, end, rank] of commands) {`.
- **Cleanup:** sortedSection tự hết scope; input array không bị mutate.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Số thứ K:** Condition của scan/simulation phải theo đúng tie-break và thứ tự rule của đề. So sánh strict hay non-strict chỉ đổi khi boundary/tie của bài chứng minh, không vì thói quen viết comparator.

### Complexity proof from movements

Gọi `m` là độ dài đoạn của một command:

- time cho command đó: `O(m log m)`;
- space: `O(m)` cho bản sao;
- toàn bài: `O(Σ m log m)`, chặn trên bởi `O(q * n log n)`.

**Proof từ operation của Số thứ K:** Tách chi phí chuẩn bị (nếu có sort) khỏi traversal. Trong traversal, mỗi item/candidate được xét đúng số lần mô tả bởi loop; không nhân các loop nối tiếp thành tích. Main loop được mô tả là `quét từng [start,end,rank] trong commands.`; movement là `for...of tự sang command kế; slice dùng end exclusive.`. Vì vậy phải cộng chi phí các phase nối tiếp và chỉ nhân khi một phase thật sự chạy trọn bên trong mỗi lượt ngoài. Auxiliary space chính là state `answer array.`, không tính output nếu convention của bài tách output.

#### 19. Làm tay, brute force và bottleneck

Command `[2,5,3]` thành slice `[1,5)`: `[5,2,6,3]`; sort số `[2,3,5,6]`; rank 3
thành index 2, trả `5`. Brute chọn minimum chưa dùng `rank` lần phải quét lại đoạn,
`O(length*rank)`; numeric sort cho mỗi command là `O(length log length)` và `slice` giữ input.
