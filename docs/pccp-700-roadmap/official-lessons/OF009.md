## 01. Contract

Mỗi process có priority và original index. Lặp lại: lấy process đầu queue; nếu còn process có priority cao hơn thì đưa process hiện tại về cuối, nếu không thì thực thi và loại nó. Trả thứ tự thực thi 1-based của process tại `location`.

Duplicate priority được phép nên target phải được nhận diện bằng original index, không bằng priority.

## 02. Bound

Input vừa phải, priority chỉ nằm trong một miền nhỏ. Có thể scan toàn queue để tìm higher mỗi vòng, nhưng frequency theo priority giúp check/update rõ ràng. Queue phải dùng head pointer, không `shift()` lặp làm dịch mảng.

## 03. Brute force

Mỗi vòng `shift()` process đầu, dùng `.some()` quét phần còn lại tìm priority cao hơn; nếu có `push`, nếu không execute. Logic gần đề nhưng có thể lặp quét và dịch array.

## 04. Bottleneck

Ta không cần biết vị trí process cao hơn, chỉ cần biết priority cao nhất còn tồn tại. Vì priority hữu hạn, lưu frequency và `highestRemaining`.

Queue bằng array + `head`: item trước head là đã lấy ra; re-enqueue bằng `push`.

## 05. Pattern

Queue simulation với metadata:

```text
dequeue at head
priority < current maximum → push back
otherwise execute, decrement frequency, maybe lower maximum
target original index → return execution count
```

## 06. State

- queue item `{priority,index}`;
- `head`: vị trí dequeue kế tiếp;
- `remainingByPriority[1..9]`;
- `highestRemaining`;
- `executed`.

## 07. Transition

Nếu process chưa đủ cao: `queue.push(process)`, không đổi frequency. Nếu execute: giảm frequency priority, tăng executed, hạ `highestRemaining` qua các mức count zero, rồi kiểm original index.

## 08. Invariant

Trước mỗi vòng, đoạn queue từ `head` đến cuối chứa đúng các process chưa thực thi theo FIFO hiện tại. Frequency đếm đúng các process đó; `highestRemaining` là priority lớn nhất có count dương. `executed` là số process đã loại vĩnh viễn.

## 09. Complexity

Với miền priority 1..9, mỗi lần hạ maximum tổng cộng tối đa 9 bước. Process có thể re-enqueue, nhưng số vòng quay bị chặn bởi các lớp priority; trong bound bài là an toàn. Space `O(n)`.

## 10. Pseudocode

```text
queue = priorities with original index
count each priority; highest = maximum
head = 0; executed = 0
while head < queue.length:
    process = queue[head]
    head = head + 1
    if process.priority < highest:
        queue.push(process)
        continue
    decrement its priority count
    executed++
    lower highest while its count is zero
    if process.index == location: return executed
```

## 13. Code bước 3 — ghép vòng lặp

```js
function lowerHighest(counts, highest) {
  while (highest > 0 && counts[highest] === 0) highest--;
  return highest;
}
```

Chỉ gọi sau một execution làm frequency thay đổi.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF009.js](../../../solutions/official/OF009.js).

```js
function targetProcessOrder(priorities, location) {
  const queue = priorities.map((priority, index) => ({ priority, index }));
  const counts = Array(10).fill(0);
  let highest = 0, head = 0, executed = 0;
  for (const priority of priorities) {
    counts[priority]++;
    highest = Math.max(highest, priority);
  }
  while (head < queue.length) {
    const process = queue[head];
    head += 1;
    if (process.priority < highest) {
      queue.push(process);
      continue;
    }
    counts[process.priority] -= 1;
    executed += 1;
    while (highest > 0 && counts[highest] === 0) {
      highest -= 1;
    }
    if (process.index === location) {
      return executed;
    }
  }
  return -1;
}
```

## 16. Edge cases

1. Một process: return 1.
2. Mọi priority bằng nhau: FIFO gốc.
3. Target priority thấp và bị quay nhiều vòng.
4. Duplicate priority với target: phải phân biệt original index.

## 17. Lỗi JavaScript thường gặp

- Dùng `shift()` lặp trên array lớn.
- Chỉ queue priority, làm mất target identity.
- Giảm frequency khi re-enqueue.
- Kiểm target ngay lúc dequeue trước khi biết có execute không.
- Dùng `Math.max(...largeArray)` không cần thiết; cập nhật max trong loop.

## 18. Bài transfer cùng pattern

- OF007: FIFO cố định nhưng batch release theo phần tử đầu.
- OF010: queue có time/capacity và event exit.
- OF054: hai logical queue dùng head pointers và invariant tổng.
- SR004: hai nguồn FIFO độc lập, chọn đúng front.

Tín hiệu: phần tử đầu có thể quay lại cuối và identity phải sống qua nhiều vòng ⇒ queue item gồm value + original metadata.

### Loop and condition derivation

- **Nhịp lặp:** `while head < queue.length`. Đây là lý do code dùng block bắt đầu bởi `while (head < queue.length) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “priority < highestRemaining”. Trong dry run `[2,1,3,2]`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (process.priority < highest) {`.
- **Tiến triển:** head++ tách riêng. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `execute thì counts--, executed++, hạ max` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `counts[priority]++;`.
- **Cleanup:** không; fallback -1. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Tiến trình:** Guard cấu trúc không rỗng phải đứng trước mọi lần đọc top/front. Equality có pop hay không, và visited được mark lúc enqueue hay dequeue, lấy đúng từ invariant của bài này.

> **Prediction checkpoint — finalization của Tiến trình:** Dòng `return -1;` chạy per current hay đúng một lần sau khi `while head < queue.length` kết thúc? Trước return, cleanup `không; fallback -1` và output `execution order` phải ở trạng thái nào? Return sớm sẽ bỏ state pending nào?

```js
function targetProcessOrder(priorities, location) {
  const queue = priorities.map((priority, index) => ({ priority, index }));
  const counts = Array(10).fill(0);
  let highest = 0, head = 0, executed = 0;
  for (const priority of priorities) {
    counts[priority]++;
    highest = Math.max(highest, priority);
  }
  while (head < queue.length) {
    const process = queue[head];
    head += 1;
    if (process.priority < highest) {
      queue.push(process);
      continue;
    }
    counts[process.priority] -= 1;
    executed += 1;
    while (highest > 0 && counts[highest] === 0) {
      highest -= 1;
    }
    if (process.index === location) {
      return executed;
    }
  }
  return -1;
}
```

#### 19. Làm bằng tay, brute force và Code Blueprint

Viết mỗi process thành thẻ `(priority, originalIndex)`. Với `[2,1,3,2]`, target index 2:
thẻ 2 và 1 về cuối vì còn priority 3; `(3,2)` chạy đầu tiên nên trả 1.

```js
function targetProcessOrderBruteForce(priorities, location) {
  const queue = priorities.map((priority, originalIndex) => {
    return { priority: priority, originalIndex: originalIndex };
  });
  let executedCount = 0;
  while (queue.length > 0) {
    const currentProcess = queue.shift();
    let hasHigherPriority = false;
    for (const waitingProcess of queue) {
      if (waitingProcess.priority > currentProcess.priority) {
        hasHigherPriority = true;
        break;
      }
    }
    if (hasHigherPriority) {
      queue.push(currentProcess);
      continue;
    }
    executedCount++;
    if (currentProcess.originalIndex === location) return executedCount;
  }
  return -1;
}
```

Brute force gần đề nhưng `shift()` dịch array và scan higher lặp lại. Frequency priority giữ
`highestRemaining`; head pointer dequeue mà không dịch array.

| State | Kiểu | Lưu chính xác gì | Init và lý do | Scope |
| --- | --- | --- | --- | --- |
| `queue`,`head` | object[]/number | FIFO và đầu logic | thẻ input, `0` | xuyên loop |
| `counts`,`highestRemaining` | array/number | frequency và max còn sống | đếm input | xuyên loop |
| `executedCount` | number | số process đã chạy | `0` | output state |
| `currentProcess` | object | thẻ vừa dequeue | `queue[head]`, rồi `head++` | iteration |

```text
OUTPUT: execution order; PREPARE: queue objects, counts; GLOBAL STATE: head,max,executed
INIT: 0, maximum, 0; MAIN LOOP: while head < queue.length
CURRENT ITEM: currentProcess=queue[head], rồi head++
PER-ITERATION STATE: currentProcess; CHECK: priority < highestRemaining

UPDATE: execute thì counts--, executed++, hạ max; POINTER MOVEMENT: head++ tách riêng
STOP / RETURN: target chỉ return sau execute; CLEANUP: không; fallback -1
```

`Contract → number 1-based`; `State → queue/count/head`; `một lượt → while queue pending`;
`Invariant → suffix từ head là pending`; `Transition → requeue hoặc execute`; `Stop → target`.

| Dequeue | max | Check | Update | executed |
| --- | ---: | --- | --- | ---: |
| `(2,0)` | 3 | thấp hơn | push cuối | 0 |
| `(1,1)` | 3 | thấp hơn | push cuối | 0 |
| `(3,2)` | 3 | execute target | count 3 giảm | 1 |

Invariant đầu vòng: `[head..queue.length)` là đúng FIFO chưa execute; counts đếm đúng tập đó.
Re-enqueue không đổi counts; execute mới giảm. Miền priority 1..9 làm tổng bước hạ max hằng số;
space queue `O(n)`. `shift()` dễ đọc hơn nhưng có chi phí dịch; head pointer cần nhớ prefix đã lấy.

- Logic: chỉ lưu priority; `[2,2]`, target 1 làm mất identity.
- Off-by-one: count từ 0; một process phải trả 1.
- Check/update: check target trước branch; `[2,1,3,2]`, target 2 lộ lỗi.
- Init: giảm count lúc re-enqueue làm max stale.
- Hidden: mọi priority bằng nhau phải giữ FIFO.
- Performance: `shift()+some()` lặp trên queue lớn.
