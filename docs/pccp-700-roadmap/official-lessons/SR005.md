# SR005 — Tiến độ bài tập

- Nguồn đề: [Programmers lesson 176962](https://school.programmers.co.kr/learn/courses/30/lessons/176962?language=javascript)
- Coverage: Stack / Implementation / Simulation

## 01. Contract

Mỗi bài có tên, giờ bắt đầu và số phút cần làm. Đúng giờ của bài mới, phải dừng bài đang làm để bắt đầu bài mới. Khi hoàn thành sớm trước event tiếp theo, tiếp tục bài bị dừng gần nhất; nếu còn thời gian thì tiếp tục pop các bài cũ hơn. Trả tên các bài theo thứ tự hoàn thành.

Đây là preemption bắt buộc và resume theo LIFO, không phải chọn bài ngắn nhất hay làm nốt bài hiện tại.

## 02. Bound

Tối đa 1.000 plans. Sort theo giờ bắt đầu `O(n log n)` đủ. Thời gian có thể chuyển thành số phút để mọi phép so sánh/trừ là số học đơn giản.

## 03. Brute force

Mô phỏng từng phút có thể chạy được với bound thời gian nhỏ, nhưng che giấu event logic và dễ sai thứ tự tại đúng phút bài mới bắt đầu. Mô phỏng theo khoảng giữa hai start time rõ hơn: chỉ trạng thái tại event mới làm quyết định thay đổi.

## 04. Bottleneck

Khoảng `available` trước bài mới có thể:

- Không đủ cho bài hiện tại: pause phần còn lại.
- Vừa đủ: bài hiện tại hoàn thành đúng lúc bài mới bắt đầu.
- Dư: hoàn thành hiện tại rồi dùng phần dư resume nhiều bài trong stack.

Nhánh thứ ba là nơi lời giải một-pop thường sai.

## 05. Pattern

Pattern là **event simulation + preemption stack**. Sort events, xử lý trọn khoảng thời gian `[start[i], start[i+1])`, lưu task chưa xong bằng `{name, remaining}`.

## 06. State

- `tasks`: plans đã parse và sort.
- `available`: số phút từ start hiện tại đến start kế tiếp.
- `paused`: stack bài bị dừng, phần tử cuối được resume trước.
- `completed`: thứ tự hoàn thành.
- `remaining`: số phút một bài còn cần.

## 07. Transition

Với task hiện tại và khoảng tới event kế:

1. Nếu `remaining > available`, trừ thời gian đã làm rồi push task vào stack.
2. Ngược lại, ghi task hoàn thành và lấy thời gian dư.
3. Trong khi còn dư, pop bài gần nhất: hoàn thành nếu đủ thời gian; nếu không đủ, cập nhật remaining rồi push lại.
4. Tại event kế, task mới luôn được ưu tiên.

Sau event cuối không còn task mới chen vào: task cuối hoàn thành, rồi pop toàn bộ stack theo LIFO.

## 08. Invariant

Sau khi xử lý khoảng trước `tasks[i+1]`:

- Mọi tên trong `completed` đã thực sự hoàn thành theo đúng thời điểm.
- `paused` chứa đúng các bài chưa xong; thứ tự đáy→đỉnh là cũ→mới.
- Mọi phút trước start kế tiếp đã được dùng tối đa hoặc là idle khi stack rỗng.

Do bài mới bắt buộc preempt, bài gần nhất bị dừng luôn là bài đầu tiên được resume; stack bảo toàn chính xác rule này.

## 09. Complexity

Sort `O(n log n)`. Mỗi task được push/pop hữu hạn lần; toàn bộ simulation `O(n)`. Tổng `O(n log n)` time và `O(n)` space.

## 10. Pseudocode

```text
parse HH:MM to minutes; sort by start
for each task except last:
  available = next.start - current.start
  if current.duration > available:
    push(current, duration-available)
  else:
    finish current
    available -= duration
    while available > 0 and stack not empty:
      resume top; finish or pause updated remainder
finish last task
pop remaining paused tasks into answer
```

## 11. Code bước 1 — chuẩn hóa thời gian

```js
function toMinutes(time) {
  const [hour, minute] = time.split(":").map(Number);
  return hour * 60 + minute;
}
```

Sau parse, `12:30 - 11:40` trở thành `750 - 700 = 50`; không cần xử lý mượn phút thủ công.

## 12. Code bước 2 — pause bài hiện tại

```js
if (current.remaining > available) {
  paused.push({
    name: current.name,
    remaining: current.remaining - available,
  });
}
```

So sánh là `>` chứ không phải `>=`: nếu bằng nhau, bài hoàn thành đúng lúc event mới tới và phải được ghi vào answer.

## 13. Code bước 3 — dùng toàn bộ thời gian dư

```js
completed.push(current.name);
available -= current.remaining;
while (available > 0 && paused.length > 0) {
  const resumed = paused.pop();
  if (resumed.remaining <= available) {
    available -= resumed.remaining;
    completed.push(resumed.name);
  } else {
    resumed.remaining -= available;
    paused.push(resumed);
    available = 0;
  }
}
```

Phải dùng `while`, vì một khoảng trống dài có thể hoàn thành nhiều bài đã pause.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/SR005.js](../../../solutions/official/SR005.js).

```js
function toMinutes(time) {
  const [hour, minute] = time.split(":").map(Number);
  return hour * 60 + minute;
}

function homeworkCompletionOrder(plans) {
  const tasks = plans
    .map(([name, start, duration]) => ({
      name,
      start: toMinutes(start),
      remaining: Number(duration),
    }))
    .sort((left, right) => left.start - right.start);

  const paused = [];
  const completed = [];

  for (let index = 0; index < tasks.length - 1; index++) {
    const current = tasks[index];
    let available = tasks[index + 1].start - current.start;

    if (current.remaining > available) {
      paused.push({ name: current.name, remaining: current.remaining - available });
      continue;
    }

    completed.push(current.name);
    available -= current.remaining;

    while (available > 0 && paused.length > 0) {
      const resumed = paused.pop();
      if (resumed.remaining <= available) {
        available -= resumed.remaining;
        completed.push(resumed.name);
      } else {
        resumed.remaining -= available;
        paused.push(resumed);
        available = 0;
      }
    }
  }

  completed.push(tasks.at(-1).name);
  while (paused.length > 0) completed.push(paused.pop().name);
  return completed;
}
```

## 15. Dry-run

Plans: `aaa 12:00/20`, `bbb 12:10/30`, `ccc 12:40/10`.

- 12:00→12:10 có 10 phút: `aaa` còn 10, push `[aaa:10]`.
- 12:10→12:40 có 30 phút: `bbb` vừa đủ, hoàn thành `bbb`.
- `ccc` là event cuối, hoàn thành `ccc`.
- Không event mới: pop stack, hoàn thành `aaa`.

Kết quả: `[bbb, ccc, aaa]`. Chi tiết quan trọng là `bbb` hoàn thành đúng 12:40 trước khi `ccc` bắt đầu.

## 16. Edge cases

- Task hoàn thành đúng giờ task kế tiếp bắt đầu.
- Một khoảng dư hoàn thành nhiều task pause.
- Khoảng dư chỉ làm được một phần task vừa pop: phải push lại remainder.
- Stack rỗng và còn thời gian: hệ thống idle.
- Nhiều task liên tiếp đều bị preempt.
- Input không theo thứ tự thời gian: bắt buộc sort.

## 17. Lỗi JavaScript thường gặp

- Sort chuỗi thời gian rồi phụ thuộc format thay vì parse rõ contract.
- Quên `Number(duration)`, dẫn tới cộng chuỗi.
- Dùng queue thay stack khi resume.
- Chỉ resume tối đa một task trong thời gian dư.
- Dùng `>=` ở nhánh pause, làm mất task vừa hoàn thành đúng event.
- Mutate mảng plans gốc ngoài ý muốn.

## 18. Bài transfer cùng pattern

- OF009: queue simulation theo event, nhưng không có resume LIFO.
- OF010: tiến trình/priority; cần xác định rõ scheduling rule trước khi chọn cấu trúc.
- OF013: heap scheduling, khác vì lựa chọn theo priority chứ không phải task gần nhất.
- OF048: parse timestamp thành scalar trước simulation.

Tín hiệu nhận dạng: **công việc mới chen ngang, việc tạm dừng gần nhất được tiếp tục trước** ⇒ sort event + stack chứa remaining work.
