# OF043 — Kiểm tra nhập cảnh

- Nguồn đề: [Programmers lesson 43238](https://school.programmers.co.kr/learn/courses/30/lessons/43238?language=javascript)
- Pattern chính: binary search on answer / first feasible
- Mức trong bank: CORE / template

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Mỗi nhân viên mất `times[i]` phút cho một người và làm liên tục. Tìm thời gian nhỏ nhất để xử lý ít nhất `n` người.

## 02. Bound

Mô phỏng từng người bằng heap là `O(n log m)` với n rất lớn. Answer nằm trên trục thời gian và predicate “xử lý đủ trong T phút” đơn điệu, nên binary search `O(m log answer)`.

## 03. Brute force

Tăng time từng phút rồi tính tổng `floor(time/times[i])` đến khi đủ. Upper bound có thể tới `10^18`, không thể scan.

## 04. Bottleneck

Ta không cần biết ai vào quầy nào; tại time T, quầy i xử lý `floor(T/times[i])`. Predicate false ở thời gian nhỏ rồi true mãi về sau.

## 05. Pattern

First feasible trên đoạn đóng:

```text
feasible(T) = sum floor(T/time_i) >= n
false ... false | true ... true
```

Nếu mid feasible giữ mid bằng `high=mid`; nếu false bỏ mid bằng `low=mid+1`.

## 06. State

- `low`, `high` BigInt;
- `middle`;
- `processed` có cutoff khi đạt target;
- durations BigInt.

## 07. Transition

Midpoint `(low+high)/2n`. Feasible ⇒ high=middle; infeasible ⇒ low=middle+1n. Loop khi `low<high`; kết thúc low là first true.

## 08. Invariant

Đáp án luôn nằm trong `[low,high]`. High ban đầu `min(times)*n` chắc chắn feasible vì quầy nhanh nhất tự xử lý đủ. Transition không loại answer: feasible mid có thể chính là answer; false mid chắc chắn nhỏ hơn answer.

## 09. Complexity

Time `O(m log(minTime*n))`, space `O(m)` do convert BigInt. BigInt tránh precision loss khi tích tới `10^18`.

## 10. Pseudocode

```text
low=0; high=min(times)*n
while low<high:
  mid=(low+high)//2
  processed=sum(mid//time)
  if processed>=n: high=mid
  else: low=mid+1
return low
```

## 11. Code bước 1 — dựng state

```js
function bounds(people, durations) {
  const target=BigInt(people);
  const fastest=durations.reduce((a,b)=>a<b?a:b);
  return [0n, fastest*target];
}
```

## 12. Code bước 2 — viết transition

```js
function canProcess(time, durations, target) {
  let count=0n;
  for (const d of durations) {
    count += time/d;
    if (count >= target) return true;
  }
  return false;
}
```

Cutoff tránh tổng tăng không cần thiết.

## 13. Code bước 3 — ghép vòng lặp

```js
function firstFeasible(low, high, predicate) {
  while (low<high) {
    const mid=(low+high)/2n;
    if (predicate(mid)) high=mid;
    else low=mid+1n;
  }
  return low;
}
```

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF043.js](../../../solutions/official/OF043.js).

```js
function minimumImmigrationTimeBigInt(people, times) {
  const target = BigInt(people);
  const durations = [];
  for (const time of times) {
    durations.push(BigInt(time));
  }

  let fastest = durations[0];
  for (const duration of durations) {
    if (duration < fastest) {
      fastest = duration;
    }
  }

  let low = 0n;
  let high = fastest * target;

  while (low < high) {
    const middle = (low + high) / 2n;
    let processed = 0n;

    for (const duration of durations) {
      processed += middle / duration;
      if (processed >= target) {
        break;
      }
    }

    if (processed >= target) {
      high = middle;
    } else {
      low = middle + 1n;
    }
  }

  return low;
}

function minimumImmigrationTime(people, times) {
  return Number(minimumImmigrationTimeBigInt(people, times));
}
```

Adapter `minimumImmigrationTime` đổi kết quả sang Number cho giao diện judge; core BigInt giữ arithmetic chính xác.

## 15. Dry-run

`n=6,times=[7,10]`: T=27 xử lý `3+2=5` false; T=28 xử lý `4+2=6` true. First feasible là 28.

## 16. Edge cases

1. Một người.
2. Một quầy.
3. Nhiều quầy cùng duration.
4. Answer vượt `Number.MAX_SAFE_INTEGER` trong core arithmetic.
5. Mid feasible đúng bằng answer.

## 17. Lỗi JavaScript thường gặp

- Dùng bitwise midpoint, ép về 32-bit.
- Trộn BigInt và Number trong cùng phép toán.
- Khi feasible đặt `high=mid-1`, rồi trả sai convention.
- Upper bound không chắc feasible.
- Không floor division; BigInt `/` tự chia nguyên.

## 18. Bài transfer cùng pattern

- OF044: binary search answer với predicate remove rocks.
- OF056: shortest unweighted state dùng BFS, không binary search.

Tín hiệu: hỏi minimum/maximum số và có predicate đơn điệu kiểm được nhanh ⇒ binary search trên answer.

## 19. Làm bằng tay và brute force executable

Với `people=6`, `times=[7,10]`, hãy thử quanh ranh giới:

| `time` | Quầy 7 phút | Quầy 10 phút | Tổng | Feasible? |
| ---: | ---: | ---: | ---: | --- |
| 27 | 3 | 2 | 5 | Không |
| 28 | 4 | 2 | 6 | Có |

Chỉ cần chứng minh 27 false và 28 true là đã khóa được first feasible bằng 28. Brute force dưới
đây diễn tả đúng định nghĩa nhưng chỉ dùng cho input nhỏ:

```js
function minimumImmigrationTimeBrute(people, times) {
  for (let time = 0; ; time += 1) {
    let processed = 0;
    for (const duration of times) {
      processed += Math.floor(time / duration);
    }
    if (processed >= people) {
      return time;
    }
  }
}
```

Brute force quét `answer + 1` mốc. Binary search giữ nguyên predicate nhưng giảm số mốc cần thử
từ tuyến tính theo answer xuống logarithm.

## 20. Bảng state và khởi tạo

| State | Ý nghĩa | Khởi tạo | Vì sao đúng |
| --- | --- | --- | --- |
| `target` | số người phải xử lý | `BigInt(people)` | cùng kiểu với mọi phép tính core |
| `durations` | thời gian mỗi quầy | đổi từng phần tử sang BigInt | không trộn Number và BigInt |
| `low` | đầu trái còn có thể chứa đáp án | `0n` | thời gian không âm |
| `high` | đầu phải chắc chắn feasible | `fastest * target` | quầy nhanh nhất tự xử lý đủ người |
| `processed` | số người xử lý được ở `middle` | `0n` mỗi vòng | predicate độc lập giữa các mid |

## 21. Blueprint từ đề đến code

1. Nhìn thấy `n` rất lớn nên loại mô phỏng từng người.
2. Đặt câu hỏi quyết định: “Trong `T` phút có xử lý đủ người không?”.
3. Viết `processed = sum(T / duration)` và nhận ra predicate `false → true`.
4. Chọn convention first feasible trên đoạn đóng `[low, high]`.
5. Dựng `high` chắc chắn true bằng `fastest * target`.
6. Giữ `middle` khi true (`high = middle`), loại nó khi false (`low = middle + 1n`).
7. Dùng BigInt xuyên suốt core và chỉ đổi sang Number ở adapter khi contract cần.

## 22. Chứng minh, lỗi lộ diện và recall

Nếu `middle` feasible thì mọi thời gian lớn hơn cũng feasible, nhưng `middle` có thể là đáp án nên
không được loại nó. Nếu `middle` false thì mọi thời gian nhỏ hơn cũng false, do đó có thể bỏ cả
đoạn tới `middle`. Mỗi transition thu hẹp interval và vẫn giữ first true; khi `low === high`, điểm
duy nhất còn lại chính là đáp án.

| Sai lầm | Test làm lộ | Kết quả đúng |
| --- | --- | ---: |
| high không chắc feasible | `1, [5,10]` | 5 |
| dùng `< target` sai phía ranh giới | `6, [7,10]` | 28 |
| overflow Number trong core | `1_000_000_000, [1_000_000_000]` | `10^18n` |
| quên cộng năng suất các quầy trùng nhau | `4, [2,2]` | 4 |

Recall: **minimum + predicate false-then-true ⇒ first feasible; high phải true; true giữ mid,
false bỏ mid; answer lớn thì BigInt từ đầu đến cuối.**

## A17. Blueprint đủ trường và Recall ba tầng

```text
OUTPUT: thời gian nhỏ nhất xử lý đủ target người.
PREPARE: chuyển target/durations sang BigInt; chọn high=fastest*target chắc chắn feasible.
GLOBAL STATE: low và high của first-feasible closed search.
INIT: low=0n; high=minDuration*target.
MAIN LOOP: while low < high.
CURRENT ITEM: middle=(low+high)/2 và processed tại middle.
PER-ITERATION STATE: processed cộng floor(middle/duration), có thể dừng khi đủ.
CHECK: processed >= target hay predicate còn false.
BRANCH: feasible giữ middle bằng high=middle; false bỏ middle bằng low=middle+1n.
UPDATE: chỉ một boundary đổi mỗi iteration, interval luôn chứa answer.
POINTER MOVEMENT: interval co; không mô phỏng từng người.
STOP / RETURN: low===high thì return low (adapter đổi Number nếu an toàn).
CLEANUP: mọi arithmetic core dùng BigInt, không trộn Number.
```

- Recall 1: Predicate đủ người false→true; high phải feasible; true giữ mid, false bỏ mid.
- Recall 2: STATE low/high → LOOP binary → CHECK processed>=target → UPDATE boundary → RETURN low.
- Recall 3: Điền `if (processed >= target) high = ___; else low = middle + ___`.
