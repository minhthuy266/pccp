# OF003 — Danh bạ điện thoại

- Nguồn đề: [Programmers lesson 42577](https://school.programmers.co.kr/learn/courses/30/lessons/42577?language=javascript)
- Pattern chính: lexicographic sort + adjacent prefix check
- Mức trong bank: CORE / representative

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Cho danh sách các số điện thoại dạng string. Trả `false` nếu tồn tại một số là prefix của một số khác; ngược lại trả `true`.

Prefix phải bắt đầu từ ký tự đầu. `"12"` là prefix của `"123"`, nhưng không phải prefix của `"312"`. Số điện thoại phải giữ dạng string để không mất chữ số đầu và để kiểm prefix.

## 02. Bound

Danh sách có thể rất lớn, nên kiểm tra mọi cặp `O(n²)` không an toàn. Mỗi chuỗi có độ dài giới hạn, vì vậy sort từ điển rồi scan adjacent với chi phí `O(n log n * L)` là phù hợp, với `L` là chi phí so chuỗi.

## 03. Brute force

Với mọi cặp `(i, j)`, `i !== j`, kiểm `phoneBook[j].startsWith(phoneBook[i])`. Nếu có thì trả false.

Có `n(n-1)` cặp có hướng; cùng một prefix relationship bị kiểm qua rất nhiều số không liên quan.

## 04. Bottleneck

Ta cần đưa các chuỗi có prefix chung nằm cạnh nhau. Lexicographic sort có đúng tính chất đó: nếu `a` là prefix của `b`, thì `a` đứng ngay trước một block các chuỗi bắt đầu bằng `a`.

Chỉ cần kiểm cặp adjacent. Nếu `a` là prefix của một chuỗi nào đó, chuỗi đầu tiên ngay sau `a` trong thứ tự sort cũng bắt đầu bằng `a`.

## 05. Pattern

Pattern `sort → local adjacency check`:

```text
copy input
lexicographic sort
for each adjacent pair (shorterCandidate, next):
    if next startsWith shorterCandidate: conflict
```

Không cần Hash; dù bài nằm trong Kit Hash, sort là lời giải trực tiếp và dễ chứng minh.

## 06. State

- `sorted`: bản sao đã sort của phone book;
- `index`: cặp đang xét là `sorted[index]`, `sorted[index + 1]`.

Không cần lưu mọi prefix đã thấy.

## 07. Transition

Tại mỗi index:

- nếu `sorted[index + 1].startsWith(sorted[index])`, return `false` ngay;
- nếu không, tăng index và xét cặp kế tiếp;
- hết scan mà không conflict, return `true`.

## 08. Invariant

Trước khi xét cặp ở `index`, không có prefix conflict nào mà phần tử đứng trước trong sorted nằm ở vị trí `< index`.

Lý do adjacent đủ: giả sử `a` là prefix của `b`. Sau sort, tất cả chuỗi bắt đầu bằng `a` tạo một đoạn liên tiếp ngay sau `a`; phần tử đầu đoạn đó adjacent với `a`, nên scan chắc chắn phát hiện.

## 09. Complexity

- Copy: `O(n)` references.
- Sort: `O(n log n * L)` theo chi phí so chuỗi.
- Scan `startsWith`: `O(n * L)`.
- Space: `O(n)` cho bản sao, chưa tính bộ nhớ sort nội bộ.

## 10. Pseudocode

```text
sorted = copy phoneBook
sort sorted lexicographically
for i from 0 to length-2:
    if sorted[i+1] starts with sorted[i]:
        return false
return true
```

## 11. Code bước 1 — dựng state

```js
function sortedPhoneBook(phoneBook) {
  return [...phoneBook].sort();
}
```

Sort mặc định là điều ta muốn ở đây: lexicographic string order. Khác OF015, không dùng `(a, b) => a - b` vì phone number không phải số để tính toán.

## 12. Code bước 2 — viết transition

```js
function adjacentHasPrefix(sorted, index) {
  const prefixCandidate = sorted[index];
  const nextNumber = sorted[index + 1];
  return nextNumber.startsWith(prefixCandidate);
}
```

Chỉ cần kiểm hướng current → next. Một chuỗi dài hơn không thể là prefix của chuỗi ngắn hơn đứng ngay trước theo cách này.

## 13. Code bước 3 — ghép vòng lặp

```js
function scanPrefixConflict(sorted) {
  for (let index = 0; index + 1 < sorted.length; index++) {
    if (adjacentHasPrefix(sorted, index)) return false;
  }
  return true;
}
```

Điều kiện `index + 1 < length` tránh truy cập phần tử sau phần tử cuối.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF003.js](../../../solutions/official/OF003.js).

```js
function hasNoPhonePrefix(phoneBook) {
  const sorted = [...phoneBook].sort();
  for (let index = 0; index + 1 < sorted.length; index++) {
    if (sorted[index + 1].startsWith(sorted[index])) return false;
  }
  return true;
}
```

## 15. Dry-run

Input `['119','97674223','1195524421']`:

| Bước | Giá trị |
|---|---|
| Sort | `['119','1195524421','97674223']` |
| Pair 0 | `'1195524421'.startsWith('119')` → true |
| Return | `false` |

Case `['911','91']` được sort thành `['91','911']`, nên dù prefix ban đầu đứng sau, scan vẫn phát hiện.

## 16. Edge cases

1. Prefix input ban đầu đứng sau chuỗi dài hơn.
2. Hai chuỗi có prefix chung nhưng không chuỗi nào là prefix của chuỗi kia, ví dụ `12`, `13`.
3. Một phần tử: không có cặp, trả true.
4. Chuỗi chỉ gồm chữ số nhưng phải giữ kiểu string.

## 17. Lỗi JavaScript thường gặp

- Convert sang Number: có thể mất leading zero và gặp precision issue.
- Dùng `.includes()` thay `.startsWith()`: substring ở giữa không phải prefix.
- Sort trực tiếp input rồi code ngoài mong input không mutate; dùng `[...phoneBook]` rõ hơn.
- Chỉ so độ dài hoặc ký tự đầu, chưa đủ.
- Vòng lặp chạy đến `index < length`, khiến `sorted[index + 1]` thành `undefined`.

## 18. Bài transfer cùng pattern

- OF015: cũng sort, nhưng numeric comparator và lấy rank.
- OF016: comparator phải dựa trên `a+b` so với `b+a`.
- OF017: sort xong tìm boundary thỏa điều kiện global.
- SR002: string scan theo chunk, state không còn là adjacent sorted item.

Tín hiệu: cần phát hiện quan hệ prefix trong tập chuỗi lớn ⇒ sort từ điển để biến quan hệ global thành check adjacent.

### Loop and condition derivation

- **Nhịp lặp:** `xét index từ 0 trong khi index+1 < length.`. Đây là lý do code dùng block bắt đầu bởi `for (let index = 0; index + 1 < sorted.length; index++) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “nextNumber.startsWith(prefixCandidate).”. Trong dry run `['119','97674223','1195524421']`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (sorted[index + 1].startsWith(sorted[index])) return false;`.
- **Tiến triển:** index tăng 1.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `không có state tích lũy khác.` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `for (let index = 0; index + 1 < sorted.length; index++) {`.
- **Cleanup:** không có.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

### Complexity proof from movements

- Copy: `O(n)` references.
- Sort: `O(n log n * L)` theo chi phí so chuỗi.
- Scan `startsWith`: `O(n * L)`.
- Space: `O(n)` cho bản sao, chưa tính bộ nhớ sort nội bộ.

**Proof từ operation của Danh bạ điện thoại:** Mỗi occurrence được đọc đúng theo vòng sở hữu nó; mỗi lần đọc gây số hữu hạn thao tác Map/Set. Nếu có sort, phần sort chi phối; nếu không, các lượt lookup/update cộng lại theo kích thước input. Main loop được mô tả là `xét index từ 0 trong khi index+1 < length.`; movement là `index tăng 1.`. Vì vậy phải cộng chi phí các phase nối tiếp và chỉ nhân khi một phase thật sự chạy trọn bên trong mỗi lượt ngoài. Auxiliary space chính là state `sorted.`, không tính output nếu convention của bài tách output.

#### 20. Brute force đầy đủ và dry-run

```js
function hasNoPhonePrefixBrute(phoneBook) {
  for (let prefixIndex = 0; prefixIndex < phoneBook.length; prefixIndex++) {
    for (let phoneIndex = 0; phoneIndex < phoneBook.length; phoneIndex++) {
      if (prefixIndex === phoneIndex) continue;

      const prefixCandidate = phoneBook[prefixIndex];
      const phoneNumber = phoneBook[phoneIndex];
      if (phoneNumber.startsWith(prefixCandidate)) return false;
    }
  }

  return true;
}
```

Với `['911','91']`, lượt `(0,1)` không khớp, lượt `(1,0)` phát hiện `911` bắt đầu bằng
`91`. Brute đúng vì xét mọi cặp có hướng, nhưng có `n(n-1)` cặp và mỗi `startsWith` còn
đọc ký tự. Sort gom toàn bộ chuỗi cùng prefix thành một block nên chỉ cần `n-1` cặp adjacent.

#### 21. Bảng state và init

| State | Kiểu | Lưu chính xác | Init | Vì sao |
| --- | --- | --- | --- | --- |
| `sorted` | `string[]` | toàn bộ số theo thứ tự từ điển | `[...phoneBook].sort()` | giữ input không bị mutate |

#### 22. Code Blueprint

```text
OUTPUT: false nếu tồn tại quan hệ prefix, ngược lại true.
PREPARE: copy rồi lexicographic sort phoneBook.
GLOBAL STATE: sorted.
INIT: index = 0; chưa loại cặp nào.
MAIN LOOP: xét index từ 0 trong khi index+1 < length.
CURRENT ITEM: prefixCandidate = sorted[index].
PER-ITERATION STATE: nextNumber = sorted[index+1].
CHECK: nextNumber.startsWith(prefixCandidate).
BRANCH: đúng thì return false.
UPDATE: không có state tích lũy khác.
POINTER MOVEMENT: index tăng 1.
STOP / RETURN: hết mọi cặp thì return true.
CLEANUP: không có.
```

Map sang code: Contract → boolean; State → bản sao sorted; Loop → `index + 1 < length`;
Invariant → mọi prefix conflict bắt đầu trước index đã bị loại; Transition → `startsWith`;
Stop → false sớm hoặc true sau vòng.
