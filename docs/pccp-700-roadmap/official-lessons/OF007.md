## 01. Contract

Tính ngày hoàn thành từng feature. Feature sau dù xong sớm vẫn không release trước feature trước; trả số feature trong mỗi batch release.

## 02. Bound

Chuyển mỗi feature thành finish day rồi scan một lần `O(n)`.

## 03. Brute force

Mô phỏng từng ngày tăng progress tất cả feature chưa release; lặp thời gian và update thừa.

## 04. Bottleneck

Progress tuyến tính cho phép tính trực tiếp finish day. Queue order biến bài thành grouping theo threshold do head quyết định.

## 05. Pattern

`finishDay=ceil((100-progress)/speed)`. Head mở batch với releaseDay; consume liên tiếp mọi finishDay `<= releaseDay`.

## 06. State

`finishDays`, `head`, `releaseDay`, `batchSize`, output.

## 07. Transition

Mỗi batch đọc day tại head, tăng head/size khi day không muộn hơn threshold, rồi push size.

## 08. Invariant

Mọi feature trước head đã được release đúng batch; feature tại head chưa release. Batch hiện tại chứa đúng prefix liên tiếp có finish day `<=` day của feature mở batch.

## 09. Complexity

Time `O(n)`, space `O(n)` cho finishDays/output.

## 10. Pseudocode

```text
compute finishDays
while head<n:
  release=finishDays[head]; size=0
  while head<n and finishDays[head]<=release: head++,size++
  append size
```

## 11. Code bước 1 — dựng state

```js
const finishDays=progresses.map((p,i)=>Math.ceil((100-p)/speeds[i]));
```

## 12. Code bước 2 — viết transition

```js
function canJoin(day,releaseDay) { return day<=releaseDay; }
```

## 13. Code bước 3 — ghép vòng lặp

```js
while (head<finishDays.length && canJoin(finishDays[head],releaseDay)) { head++; size++; }
```

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF007.js](../../../solutions/official/OF007.js).

```js
function featureDeploymentBatches(progresses,speeds) {
  const days=progresses.map((p,i)=>Math.ceil((100-p)/speeds[i]));
  const result=[]; let head=0;
  while (head<days.length) {
    const release=days[head]; let size=0;
    while (head<days.length && days[head]<=release) { head++; size++; }
    result.push(size);
  }
  return result;
}
```

## 16. Edge cases

Một feature; mọi feature cùng batch; finish days tăng; feature sau xong sớm.

## 17. Lỗi JavaScript thường gặp

Sort finishDays làm mất queue order; dùng floor; mô phỏng từng ngày; dùng `<` thay `<=`; quên advance head.

- OF052: fixed-size window, không batch threshold.

Tín hiệu: output phải giữ order và phần tử đầu khóa mốc cho các phần tử sau ⇒ queue batch scan.

### Loop and condition derivation

- **Nhịp lặp:** `while head < n vì số batch chưa biết trước`. Đây là lý do code dùng block bắt đầu bởi `while (head<days.length) {`, thay vì chọn loop theo thói quen.

- **Tiến triển:** head chỉ tiến. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `head++, batchSize++` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `while (head<days.length && days[head]<=release) { head++; size++; }`.

### Additional preserved problem-specific drills and notes

#### 19. Làm bằng tay → code blueprint → recall

Với ngày hoàn thành `[7,3,9]`, feature đầu khóa ngày release 7. Feature ngày 3 đã xong nên đi
cùng batch; ngày 9 chưa xong nên mở batch kế. Không sort vì thứ tự queue là một phần contract.

```js
function featureDeploymentBruteForce(progresses, speeds) {
  const currentProgresses = progresses.slice();
  const answer = [];
  let head = 0;
  while (head < currentProgresses.length) {
    for (let index = head; index < currentProgresses.length; index++) {
      currentProgresses[index] += speeds[index];
    }
    if (currentProgresses[head] < 100) continue;
    let batchSize = 0;
    while (head < currentProgresses.length && currentProgresses[head] >= 100) {
      head++;
      batchSize++;
    }
    answer.push(batchSize);
  }
  return answer;
}
```

Simulation đúng nhưng cập nhật cùng feature lặp theo số ngày. Công thức `ceil((100-p)/speed)`
giữ thẳng ngày hoàn thành; scan batch sau đó đọc mỗi feature đúng một lần.

| State | Kiểu | Lưu gì | Tại sao | Init | Vì sao | Scope |
| --- | --- | --- | --- | --- | --- | --- |
| `finishDays` | number[] | ngày xong từng feature | bỏ simulation ngày | tính một lần | progress tuyến tính | toàn hàm |
| `head` | number | feature đầu chưa release | queue logic | `0` | chưa release gì | xuyên outer loop |
| `answer` | number[] | size các batch đã chốt | output | `[]` | chưa có batch | toàn hàm |
| `releaseDay` | number | mốc do head khóa | check batch | `finishDays[head]` | reset mỗi batch | iteration ngoài |
| `batchSize` | number | số item batch hiện tại | ghi output | `0` | batch mới rỗng | iteration ngoài |

```text
OUTPUT: answer; PREPARE: finishDays bằng ceil; GLOBAL STATE: answer, head
INIT: [], 0; MAIN LOOP: while head < n vì số batch chưa biết trước
CURRENT ITEM: finishDays[head]; PER-ITERATION STATE: releaseDay, batchSize=0
CHECK: head<n và finishDays[head] <= releaseDay
BRANCH: nested while gom được nhiều feature; UPDATE: head++, batchSize++
POINTER MOVEMENT: head chỉ tiến; STOP / RETURN: inner dừng ở feature muộn, outer hết n
CLEANUP: answer.push(batchSize) sau inner loop; RETURN: answer
```

Invariant đầu outer loop: `[0,head)` đã được release đúng batch; `head` là feature chưa release
đầu tiên. Trong inner loop, batch chứa đúng prefix liên tiếp có finish day không vượt mốc. Vì
head chỉ tiến, nested `while` vẫn `O(n)` tổng; `finishDays` và output dùng `O(n)` space.

| Lượt | head trước | releaseDay | Inner consume | head sau | answer |
| --- | ---: | ---: | --- | ---: | --- |
| 1 | 0 | 7 | ngày 7, 3 (`while` hai lần) | 2 | `[2]` |
| 2 | 2 | 9 | ngày 9 | 3 | `[2,1]` |

- Logic: sort days; `[7,3,9]` sẽ sai grouping.
- Off-by-one: dùng `<`; `[3,3]` phải cùng batch.
- Check/update: push batch trước khi inner loop xong; `[7,3]` lộ lỗi.
- Init: không reset `batchSize`; `[1,2]` cho batch sau bị cộng dồn.
- Hidden: một feature; `[99],[1] → [1]`.
- Performance: simulation với progress nhỏ/speed nhỏ cập nhật theo ngày.

