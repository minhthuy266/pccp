# OF048 — Hạn lưu trữ dữ liệu cá nhân

- Nguồn đề: [Programmers lesson 150370](https://school.programmers.co.kr/learn/courses/30/lessons/150370?language=javascript)
- Pattern chính: parsing + scalar date + Hash lookup
- Mức trong bank: CORE / implementation

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Mọi tháng được quy ước đúng 28 ngày. `terms` ánh xạ mã điều khoản sang số tháng lưu trữ. Mỗi privacy có ngày bắt đầu và mã. Tại `today`, trả index 1-based của các privacy đã hết hạn theo thứ tự tăng dần.

Nếu ngày hết hạn exclusive bằng today thì dữ liệu đã phải hủy.

## 02. Bound

Dữ liệu không lớn, nhưng so date bằng string hoặc xử lý mượn ngày/tháng thủ công dễ lỗi. Quy ước 28 ngày cho phép đổi mọi date thành một số ngày tuyến tính và so `O(1)`.

## 03. Brute force

Cho từng privacy, cộng term từng tháng/ngày trên ba field year-month-day, xử lý overflow và trừ một ngày cuối hiệu lực. Đúng nếu cực kỳ cẩn thận nhưng nhiều boundary.

## 04. Bottleneck

Date ba chiều gây mượn/carry. Đổi sang serial day làm phép cộng term thành `start + months*28`. Dùng mốc hết hạn exclusive tránh phép “trừ một ngày” riêng.

## 05. Pattern

Normalize then compare:

```text
date → scalar day
term code → months Map
expiryExclusive = startSerial + months*28
expired iff expiryExclusive <= todaySerial
```

## 06. State

- `termMonths: Map<code, months>`;
- `todaySerial`;
- từng privacy: `startDate`, `code`, `expiryExclusive`;
- `expired` index output.

## 07. Transition

Parse `YYYY.MM.DD` bằng split và Number. Serial dùng `(month-1)`, `(day-1)` để mốc đầu năm có offset zero. Với mỗi privacy, lookup months, cộng duration và so.

## 08. Invariant

`dateToSerial` bảo toàn thứ tự ngày vì mỗi năm có `12*28` ngày và mỗi tháng 28 ngày. Sau khi xử lý `i` privacy, output chứa đúng index hết hạn trong prefix, vốn tăng dần do scan input.

## 09. Complexity

- Build terms `O(t)`.
- Scan privacies `O(p)`.
- Space `O(t+p)` tính cả output.

## 10. Pseudocode

```text
parse terms into map
todayDay = serial(today)
for privacy at index i:
    parse start, code
    expiry = serial(start) + terms[code]*28
    if expiry <= todayDay: append i+1
return output
```

## 11. Code bước 1 — dựng state

```js
function dateToSerial(date) {
  const [year, month, day] = date.split(".").map(Number);
  return year * 12 * 28 + (month - 1) * 28 + (day - 1);
}
```

Mốc tuyệt đối tùy ý; chỉ hiệu và thứ tự quan trọng.

## 12. Code bước 2 — viết transition

```js
function parseTerms(terms) {
  const map = new Map();
  for (const term of terms) {
    const [code, rawMonths] = term.split(" ");
    map.set(code, Number(rawMonths));
  }
  return map;
}
```

Không so mã term bằng nhiều `if`; Map phản ánh đúng lookup contract.

## 13. Code bước 3 — ghép vòng lặp

```js
function isExpired(startDate, months, todaySerial) {
  const expiryExclusive = dateToSerial(startDate) + months * 28;
  return expiryExclusive <= todaySerial;
}
```

Dấu `<=` là boundary quan trọng.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF048.js](../../../solutions/official/OF048.js).

```js
const DAYS_PER_MONTH = 28;
const MONTHS_PER_YEAR = 12;

function dateToSerial(date) {
  const [year, month, day] = date.split(".").map(Number);
  return (
    year * MONTHS_PER_YEAR * DAYS_PER_MONTH +
    (month - 1) * DAYS_PER_MONTH +
    (day - 1)
  );
}

function expiredPrivacyIndices(today, terms, privacies) {
  const termMonths = new Map();
  for (const term of terms) {
    const [code, rawMonths] = term.split(" ");
    termMonths.set(code, Number(rawMonths));
  }

  const todaySerial = dateToSerial(today);
  const expired = [];

  for (let index = 0; index < privacies.length; index++) {
    const [startDate, code] = privacies[index].split(" ");
    const expiryExclusive =
      dateToSerial(startDate) + termMonths.get(code) * DAYS_PER_MONTH;
    if (expiryExclusive <= todaySerial) {
      expired.push(index + 1);
    }
  }

  return expired;
}
```

## 15. Dry-run

Start `2022.01.01`, term 1 tháng: expiry exclusive là `2022.02.01`. Today đúng `2022.02.01` ⇒ `expiry <= today` ⇒ đã hết hạn. Today `2022.01.28` thì chưa.

## 16. Edge cases

1. Expiry đúng today.
2. Qua tháng 12 sang năm sau.
3. Ngày 28 sang ngày 1 tháng kế.
4. Nhiều privacy cùng term.
5. Không privacy nào hết hạn.

## 17. Lỗi JavaScript thường gặp

- Dùng `new Date()` với lịch thật 30/31 ngày, trái quy ước đề.
- So chuỗi sau khi tự cộng date không normalize.
- Dùng `<` thay `<=`.
- Quên output 1-based.
- Không `Number(rawMonths)`, dựa vào coercion.

## 18. Bài transfer cùng pattern

- OF049: parse command rồi validate transition grid.
- OF050: event lookup bằng Map và mutate state.
- SR005: parse time thành phút scalar trước event sort.

Tín hiệu: domain có đơn vị quy ước cố định ⇒ normalize về scalar rồi làm arithmetic/compare.

## 19. Làm bằng tay và brute force đầy đủ

Với today `2022.02.01`, privacy `2022.01.01 A`, term `A 1`, lịch 28 ngày cho mốc hết
hạn exclusive đúng `2022.02.01`; bằng today nghĩa là đã hết hạn. Bản brute force cộng từng
ngày giúp thấy boundary nhưng làm thừa:

```js
function expiresByDailySimulation(startDate, months, today) {
  let currentDay = dateToSerial(startDate);
  const duration = months * 28;

  for (let elapsed = 0; elapsed < duration; elapsed++) {
    currentDay += 1;
  }

  return currentDay <= dateToSerial(today);
}
```

Loop đúng vì tiến đúng số ngày hiệu lực, nhưng lặp theo duration. Scalar arithmetic thay cả
loop bằng `startSerial + months*28`; đây là cùng transition được gộp, không đổi semantics.

## 20. Bảng state và init

| State | Kiểu | Lưu chính xác | Init | Vì sao |
| --- | --- | --- | --- | --- |
| `termMonths` | `Map<string,number>` | duration tháng của từng code | `new Map()` | chưa parse term |
| `todaySerial` | `number` | today trong lịch 28 ngày | `dateToSerial(today)` | mốc so cố định |
| `expired` | `number[]` | index 1-based hết hạn trong prefix | `[]` | chưa xét privacy |
| `expiryExclusive` | `number` | ngày đầu tiên privacy không còn hiệu lực | start + months×28 | state mỗi record |

## 21. Code Blueprint

```text
OUTPUT: index 1-based của privacy hết hạn theo input order.
PREPARE: parse terms vào Map; normalize today thành scalar.
GLOBAL STATE: termMonths, todaySerial, expired.
INIT: Map/output rỗng; todaySerial tính một lần.
MAIN LOOP: scan privacies theo index tăng.
CURRENT ITEM: startDate và code của privacy hiện tại.
PER-ITERATION STATE: expiryExclusive.
CHECK: expiryExclusive <= todaySerial.
BRANCH: đúng thì push index+1.
UPDATE: output chỉ tăng; không sửa input.
POINTER MOVEMENT: index += 1.
STOP / RETURN: hết input return expired.
CLEANUP: không có.
```

Invariant: trước index `i`, output chứa đúng và theo thứ tự mọi record hết hạn trong
`privacies[0..i)`. Normalize bảo toàn thứ tự thời gian; dấu `<=` áp đúng exclusive boundary.

## 22. Ma trận lỗi và recall

| Lỗi | Revealing test | Kết quả đúng |
| --- | --- | --- |
| dùng `<` | today `2022.02.01`, start `2022.01.01`, term 1 | expired |
| lịch thật 30/31 ngày | start `2022.01.28`, term 1 | expiry `2022.02.28` |
| output 0-based | privacy đầu hết hạn | `[1]` |
| không qua năm | start `2022.12.28`, term 1 | expiry `2023.01.28` |

- **Recall 1:** parse → normalize ngày → lookup tháng → expiry exclusive → `<= today`.
- **Recall 2:** `Map terms / todaySerial / scan / push index+1`.
- **Recall 3:** điền `expiry = dateToSerial(start) + ___ * ___`; condition là `___ <= ___`.
