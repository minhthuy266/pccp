# OF010 — Xe tải qua cầu

- Nguồn đề: [Programmers lesson 42583](https://school.programmers.co.kr/learn/courses/30/lessons/42583?language=javascript)
- Pattern chính: queue + discrete-time simulation
- Mức trong bank: CORE / integration

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Xe chờ theo FIFO. Cầu có chiều dài `bridgeLength`, giới hạn tổng trọng lượng `weight`, và mỗi giây tối đa một xe vào. Một xe mất đúng `bridgeLength` giây từ lúc vào đến lúc ra. Tính thời gian khi xe cuối đã ra khỏi cầu.

Trong cùng một thời điểm, xe đến hạn ra phải được loại trước khi xét xe mới vào, vì trọng lượng vừa được giải phóng.

## 02. Bound

Không cần mô phỏng từng ô cầu cho từng xe. Chỉ lưu xe đang trên cầu cùng `exitTime`. Mỗi xe enqueue và dequeue đúng một lần; mô phỏng theo giây nằm trong bound official.

## 03. Brute force

Giữ array dài bằng cầu, mỗi giây `shift()` một ô, `push()` xe hoặc zero, rồi tính lại tổng array. Đúng nhưng dịch/tính tổng lặp lại.

## 04. Bottleneck

Ta chỉ cần biết tổng weight hiện tại và thời điểm xe đầu queue rời cầu. Lưu `{weight, exitTime}` loại bỏ việc dịch một “cầu ô vuông” và cộng lại toàn bộ.

## 05. Pattern

Discrete event theo tick:

```text
time++
release mọi xe có exitTime == time
if next truck fits: enter, exitTime=time+bridgeLength
```

## 06. State

- `onBridge` queue event `{weight, exitTime}` và `head`;
- `nextTruck` index xe chờ;
- `currentWeight`;
- `time`.

## 07. Transition

Mỗi tick xử lý `exit → enter`. Exit trừ weight và tăng head. Enter cộng weight, push event, tăng nextTruck. Dừng khi không còn xe chờ lẫn xe trên cầu.

## 08. Invariant

Đầu mỗi lần xét enter tại `time`, queue từ head chứa đúng xe vẫn trên cầu sau mọi exit của thời điểm đó; `currentWeight` bằng tổng weight của chúng. Mọi xe đã enter có exitTime cố định và queue theo thứ tự không giảm.

## 09. Complexity

- Queue operations: `O(n)` tổng.
- Tick simulation: `O(answerTime)`.
- Space: `O(n)` worst case.

Có thể jump event khi không xe nào vào được, nhưng không cần cho bound bài.

## 10. Pseudocode

```text
time=0, currentWeight=0, next=0, queue empty
while waiting truck exists or bridge not empty:
    time++
    if front exits now: dequeue and subtract weight
    if next truck fits:
        enqueue(weight, time+bridgeLength)
        add weight; next++
return time
```

## 12. Code bước 2 — viết transition

```js
function releaseAt(state) {
  if (state.head < state.onBridge.length && state.onBridge[state.head].exitTime === state.time) {
    state.currentWeight -= state.onBridge[state.head].weight;
    state.head++;
  }
}
```

Theo rule tối đa một xe vào mỗi giây và cùng travel time, tối đa một xe ra mỗi giây.

## 13. Code bước 3 — ghép vòng lặp

```js
function canEnter(currentWeight, nextWeight, limit) {
  return currentWeight + nextWeight <= limit;
}
```

Check sau release, không check trên state của giây trước.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF010.js](../../../solutions/official/OF010.js).

```js
function bridgeCrossingTime(bridgeLength, weightLimit, trucks) {
  const onBridge = [];
  let bridgeHead = 0;
  let nextTruckIndex = 0;
  let currentBridgeWeight = 0;
  let time = 0;

  while (nextTruckIndex < trucks.length || bridgeHead < onBridge.length) {
    time += 1;

    const bridgeHasTruck = bridgeHead < onBridge.length;
    if (bridgeHasTruck) {
      const firstTruckOnBridge = onBridge[bridgeHead];
      if (firstTruckOnBridge.exitTime === time) {
        currentBridgeWeight -= firstTruckOnBridge.weight;
        bridgeHead += 1;
      }
    }

    const waitingTruckExists = nextTruckIndex < trucks.length;
    if (waitingTruckExists) {
      const nextTruckWeight = trucks[nextTruckIndex];
      const nextTruckFits = currentBridgeWeight + nextTruckWeight <= weightLimit;
      if (nextTruckFits) {
        const exitTime = time + bridgeLength;
        onBridge.push({ weight: nextTruckWeight, exitTime: exitTime });
        currentBridgeWeight += nextTruckWeight;
        nextTruckIndex += 1;
      }
    }
  }

  return time;
}
```

## 16. Edge cases

1. Một xe: answer `bridgeLength + 1` theo timeline vào ở giây 1.
2. Cầu dài 1: xe trước ra rồi xe sau có thể vào cùng tick.
3. Mỗi xe gần bằng limit: đi lần lượt.
4. Nhiều xe nhẹ cùng tồn tại nhưng mỗi giây chỉ một xe vào.

## 17. Lỗi JavaScript thường gặp

- Xử lý enter trước exit ở cùng time.
- Quên trừ `currentWeight` khi dequeue.
- Dùng `shift()` lặp.
- Gán exit `time+bridgeLength-1`, lệch timeline.
- Dừng khi xe cuối vào thay vì khi xe cuối ra.

## 18. Bài transfer cùng pattern

- OF009: queue re-enqueue không có clock.

### Loop and condition derivation

- **Nhịp lặp:** `while còn xe chờ hoặc còn xe trên cầu`. Đây là lý do code dùng block bắt đầu bởi `while (nextTruckIndex < trucks.length \|\| bridgeHead < onBridge.length) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “event có ra ở time này? xe mới có vừa capacity?”. Trong dry run `[7,4]`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (bridgeHasTruck) {`.
- **Tiến triển:** bridgeHead/nextTruckIndex chỉ tiến sau transition tương ứng. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `release → subtract+head++; enter → push+add+nextIndex++` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `time += 1;`.
- **Cleanup:** không có; loop đã chờ xe cuối ra. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Xe tải qua cầu:** Guard cấu trúc không rỗng phải đứng trước mọi lần đọc top/front. Equality có pop hay không, và visited được mark lúc enqueue hay dequeue, lấy đúng từ invariant của bài này.

### Complexity proof from movements

- Queue operations: `O(n)` tổng.
- Tick simulation: `O(answerTime)`.
- Space: `O(n)` worst case.

Có thể jump event khi không xe nào vào được, nhưng không cần cho bound bài.

#### 19. Tự đi từ timeline đến code

##### Làm bằng tay

Cầu dài 2, limit 10, xe `[7,4]`:

- giây 1: xe 7 vào và được ghi `exitTime = 3`;
- giây 2: xe 4 chưa vào được vì `7 + 4 > 10`;
- giây 3: **xe 7 ra trước**, bridge weight về 0, rồi xe 4 mới được xét vào;
- xe 4 có `exitTime = 5`; chỉ khi nó ra ở giây 5 mới kết thúc.

Từ câu chuyện này sinh ra thứ tự code `time++ → release → try enter`, không phải đoán.

##### Brute force đầy đủ: mô hình cầu bằng các ô thời gian

```js
function bridgeCrossingTimeBruteForce(bridgeLength, weightLimit, trucks) {
  const bridgeSlots = Array(bridgeLength).fill(0);
  let nextTruckIndex = 0;
  let time = 0;

  while (nextTruckIndex < trucks.length || bridgeSlots.some((weight) => weight > 0)) {
    time++;
    bridgeSlots.shift();

    let currentBridgeWeight = 0;
    for (const truckWeight of bridgeSlots) {
      currentBridgeWeight += truckWeight;
    }

    const nextTruckWeight = trucks[nextTruckIndex];
    const waitingTruckExists = nextTruckIndex < trucks.length;
    const nextTruckFits = currentBridgeWeight + nextTruckWeight <= weightLimit;

    if (waitingTruckExists && nextTruckFits) {
      bridgeSlots.push(nextTruckWeight);
      nextTruckIndex++;
    } else {
      bridgeSlots.push(0);
    }
  }

  return time;
}
```

Baseline đúng vì mỗi slot biểu diễn một giây di chuyển. Nút thắt là `shift()`, `.some()` và
cộng lại bridge weight ở mọi tick. Ta chỉ cần giữ các xe thật đang trên cầu, tổng weight hiện
tại và thời điểm từng xe ra.

##### Transition và invariant

Trong một tick:

1. tăng `time`;
2. nếu event đầu có `exitTime === time`, trừ weight rồi tăng `bridgeHead`;
3. nếu còn xe chờ, đọc `nextTruckWeight`;
4. check `currentBridgeWeight + nextTruckWeight <= weightLimit`;
5. nếu vừa, push event với `exitTime = time + bridgeLength`, cộng weight, tăng index;
6. nếu không vừa, không thay đổi queue xe chờ;
7. dừng chỉ khi không còn xe chờ **và** không còn event sống trên cầu.

Ngay trước bước xét enter, suffix `onBridge[bridgeHead..]` chứa đúng xe còn trên cầu và
`currentBridgeWeight` bằng tổng weight của suffix đó. Release trước enter khôi phục invariant
cho đúng thời điểm hiện tại; enter chỉ commit nếu capacity vẫn hợp lệ.

##### Code Blueprint

```text
OUTPUT: time khi xe cuối ra
PREPARE: event queue onBridge
GLOBAL STATE: onBridge, bridgeHead, nextTruckIndex, currentBridgeWeight, time
INIT: [], 0, 0, 0, 0
MAIN LOOP: while còn xe chờ hoặc còn xe trên cầu
CURRENT ITEM: event đầu cầu và xe chờ đầu tiên
PER-ITERATION STATE: bridgeHasTruck, waitingTruckExists, nextTruckFits, exitTime
CHECK: event có ra ở time này? xe mới có vừa capacity?

```
