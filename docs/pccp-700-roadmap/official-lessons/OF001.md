# OF001 — Người chưa hoàn thành

- Nguồn đề: [Programmers lesson 42576](https://school.programmers.co.kr/learn/courses/30/lessons/42576?language=javascript)
- Pattern chính: frequency map + multiset difference
- Mức trong bank: CORE / first principle

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

`participant` chứa tên tất cả người tham gia. `completion` chứa tên người đã hoàn thành và ít hơn đúng một phần tử. Tên có thể trùng nhau, nên cần trả tên của đúng một occurrence còn thiếu chứ không phải tìm một giá trị chỉ xuất hiện ở một phía.

Output là một string: tên người không hoàn thành.

## 02. Bound

Danh sách có thể lớn, nên so từng participant với toàn bộ completion sẽ thành `O(n²)`. Tên ngắn nhưng duplicate được phép; cần lời giải gần tuyến tính theo số phần tử.

`Map<string, number>` cho lookup/update trung bình `O(1)`, đưa tổng thời gian về `O(n)` trung bình và bộ nhớ `O(u)`, với `u` là số tên khác nhau.

## 03. Brute force

Với mỗi tên trong `completion`, tìm một occurrence bằng nhau trong bản sao `participant` rồi xóa nó. Phần tử còn lại là đáp án.

Nếu mỗi lần dùng `findIndex`/`splice`, ta có tối đa `n` lần quét mảng dài `n`: `O(n²)`; `splice` còn dịch phần đuôi.

## 04. Bottleneck

Brute force liên tục hỏi “tên này còn bao nhiêu occurrence chưa ghép?” nhưng lại đi tìm từ đầu. Ta chỉ cần lưu trực tiếp con số đó theo tên.

Set không đủ vì Set chỉ lưu có/không: hai người cùng tên sẽ bị gộp thành một.

## 05. Pattern

Đây là hiệu của hai multiset:

```text
count toàn bộ participant
trừ một cho từng completion
key còn count dương là đáp án
```

Pattern áp dụng khi identity có thể lặp và ta cần so chênh lệch số lần xuất hiện.

## 06. State

`remainingByName: Map<string, number>`.

Ý nghĩa value phải phát biểu chính xác: số occurrence của `name` đã thấy trong participant nhưng chưa bị một occurrence completion tương ứng triệt tiêu.

## 07. Transition

- Đọc participant `name`: `count[name] += 1`.
- Đọc completion `name`: `count[name] -= 1`.
- Sau khi trừ xong: tìm entry có value `> 0`.

Không cần xóa key khi count về `0`; giữ `0` không ảnh hưởng tính đúng.

## 08. Invariant

Sau khi đếm `p` participant và trừ `c` completion, với mọi tên `x`:

```text
remainingByName[x]
= số lần x trong participant[0..p)
- số lần x trong completion[0..c)
```

Khi xử lý hết hai mảng, đề bảo đảm tổng count còn lại bằng `1`, nên đúng một tên có count dương.

## 09. Complexity

- Time trung bình: `O(n)` Map operations.
- Space: `O(u)` với `u` tên khác nhau.
- Chi phí hash string còn phụ thuộc độ dài tên, nhưng tên bị giới hạn ngắn trong đề.

## 10. Pseudocode

```text
counts = empty map
for name in participant:
    counts[name] = counts[name] + 1
for name in completion:
    counts[name] = counts[name] - 1
for (name, count) in counts:
    if count > 0: return name
```

## 11. Code bước 1 — dựng state

```js
function countParticipants(participant) {
  const remainingByName = new Map();
  for (const name of participant) {
    remainingByName.set(name, (remainingByName.get(name) ?? 0) + 1);
  }
  return remainingByName;
}
```

`?? 0` chỉ dùng `0` khi key chưa tồn tại; rõ nghĩa hơn dựa vào truthiness.

## 12. Code bước 2 — viết transition

```js
function subtractCompletions(remainingByName, completion) {
  for (const name of completion) {
    remainingByName.set(name, remainingByName.get(name) - 1);
  }
  return remainingByName;
}
```

Theo contract, mọi occurrence trong completion đều có occurrence tương ứng trong participant, nên `get(name)` tồn tại.

## 13. Code bước 3 — ghép vòng lặp

```js
function findPositiveEntry(remainingByName) {
  for (const [name, remaining] of remainingByName) {
    if (remaining > 0) return name;
  }
  return "";
}
```

Fallback chỉ giúp function total; với input hợp lệ của đề, code luôn return trong loop.

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF001.js](../../../solutions/official/OF001.js).

```js
function unfinishedParticipant(participant, completion) {
  const remainingByName = new Map();
  for (const name of participant) {
    remainingByName.set(name, (remainingByName.get(name) ?? 0) + 1);
  }
  for (const name of completion) {
    remainingByName.set(name, remainingByName.get(name) - 1);
  }
  for (const [name, remaining] of remainingByName) {
    if (remaining > 0) return name;
  }
  return "";
}
```

## 15. Dry-run

| Phase | mislav | stanko | ana |
|---|---:|---:|---:|
| Count participant | 2 | 1 | 1 |
| Trừ `stanko` | 2 | 0 | 1 |
| Trừ `ana` | 2 | 0 | 0 |
| Trừ `mislav` | 1 | 0 | 0 |

Entry dương còn lại là `mislav`.

## 16. Edge cases

1. Một participant, completion rỗng.
2. Tất cả participant cùng tên; count phải giữ multiplicity.
3. Người thiếu xuất hiện ở đầu hoặc cuối input không quan trọng.
4. Completion có thứ tự hoàn toàn khác participant.

## 17. Lỗi JavaScript thường gặp

- Dùng `new Set(participant)`: mất duplicate.
- `map.get(name) + 1` khi key chưa có: tạo `NaN`.
- Dùng object thường với key tùy ý mà không cân nhắc prototype; `Map` an toàn và rõ hơn.
- Sort rồi quên numeric/string semantics không liên quan nhưng làm solution dài hơn cần thiết.
- Trả key có count khác `0` trước khi trừ hết completion.

## 18. Bài transfer cùng pattern

- OF004: vẫn đếm theo key nhưng value được đưa vào công thức tổ hợp.
- OF052: frequency map phải cập nhật khi cửa sổ trượt vào/ra.
- OF058: Map count kết hợp two pointers và điều kiện cover đủ loại.

Tín hiệu: duplicate hợp lệ + cần biết chênh lệch số lượng ⇒ frequency Map, không phải Set.

### Loop and condition derivation

- **Nhịp lặp:** `một vòng cộng participant, một vòng trừ completion, một vòng tìm phần dư.`. Đây là lý do code dùng block bắt đầu bởi `for (const [name, remaining] of remainingByName) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “ở vòng cuối, remaining > 0 hay không.”. Trong dry run `['mislav','stanko','mislav','ana']`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (remaining > 0) return name;`.
- **Tiến triển:** for...of tự sang occurrence kế tiếp.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `participant set old+1; completion set old-1.` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `for (const [name, remaining] of remainingByName) {`.
- **Cleanup:** không cần xóa entry count 0.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Người chưa hoàn thành:** Với Map/Set, phải phân biệt key chưa tồn tại với count bằng 0 và membership với multiplicity. Default, increment, decrement hoặc delete chỉ xuất hiện nếu contract của bài cần đúng transition đó.

#### 20. Brute force đầy đủ và dry-run

```js
function unfinishedParticipantBrute(participant, completion) {
  const unmatched = [...participant];

  for (const completedName of completion) {
    const matchedIndex = unmatched.findIndex((participantName) => {
      return participantName === completedName;
    });
    unmatched.splice(matchedIndex, 1);
  }

  return unmatched[0];
}
```

Với ví dụ trên, `unmatched` đổi lần lượt từ `['an','binh','an']` thành `['binh','an']`,
rồi `['an']`. Code đúng vì mỗi completion xóa đúng một occurrence tương ứng. Nhưng
`findIndex` quét lại và `splice` dịch phần đuôi, nên tổng thời gian là `O(n²)`.
