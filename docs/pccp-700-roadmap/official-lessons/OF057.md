# OF057 — Hệ thống đánh chặn

- Nguồn đề: [Programmers lesson 181188](https://school.programmers.co.kr/learn/courses/30/lessons/181188?language=javascript)
- Pattern chính: interval greedy theo endpoint sớm nhất
- Mức trong bank: CORE / interval greedy

Tài liệu diễn giải lại contract để học; trang Programmers ở trên là nguồn đề chuẩn.

## 01. Contract

Mỗi mục tiêu bay qua interval mở `(s,e)` trên trục x. Một phát bắn tại tọa độ x chặn mọi interval chứa x. Không được bắn đúng endpoint. Trả số phát ít nhất để chặn toàn bộ.

## 02. Bound

Không thể thử mọi tập tọa độ. Sort interval theo end rồi scan `O(n log n)` phù hợp cho input lớn.

## 03. Brute force

Chọn một điểm đại diện trong mỗi interval, thử mọi subset rồi kiểm cover. Số subset exponential và tọa độ thực vô hạn.

## 04. Bottleneck

Trong interval có end nhỏ nhất chưa cover, mọi lời giải bắt buộc đặt một shot trước end đó. Đặt shot “sát bên trái end” giữ khả năng cover tối đa các interval sau; đặt sớm hơn không có lợi.

## 05. Pattern

Sort end tăng dần. `lastEnd` đại diện shot tại `lastEnd - ε`. Interval `[start,end]` mới đã được cover khi `start < lastEnd`; nếu `start >= lastEnd`, cần shot mới và đặt boundary thành `end`.

## 06. State

- `sorted` interval theo end;
- `lastEnd`: endpoint của shot `end-ε` gần nhất;
- `shots`.

## 07. Transition

Với `[start,end]`: nếu `start >= lastEnd`, increment shots và `lastEnd=end`; ngược lại giữ state vì shot hiện tại nằm trong interval.

## 08. Invariant

Sau prefix sorted, `shots` là minimum cho prefix và shot cuối có thể được dịch tới sát `lastEnd` mà vẫn cover nhóm cuối. Exchange argument: mọi solution phải bắn trước earliest end; thay shot đó bằng `end-ε` không làm mất interval nào trong nhóm đang overlap.

## 09. Complexity

Time `O(n log n)` do sort, scan `O(n)`, space `O(n)` vì copy input.

## 10. Pseudocode

```text
sort targets by end
shots=0; lastEnd=-infinity
for [start,end]:
  if start >= lastEnd:
    shots++; lastEnd=end
return shots
```

## 12. Code bước 2 — viết transition

```js
function needsNewShot(start, lastEnd) {
  return start >= lastEnd;
}
```

Dấu `>=` đến từ interval mở: start đúng endpoint cũ không chứa `end-ε` của group cũ.

## 13. Code bước 3 — ghép vòng lặp

```js
function countShots(sorted) {
  let shots=0, lastEnd=-Infinity;
  for (const [start,end] of sorted) {
    if (needsNewShot(start,lastEnd)) { shots++; lastEnd=end; }
  }
  return shots;
}
```

## 14. Code hoàn chỉnh

Code executable: [solutions/official/OF057.js](../../../solutions/official/OF057.js).

```js
function minimumInterceptors(targets) {
  const sortedTargets = [...targets].sort((first, second) => first[1] - second[1]);
  let interceptorCount = 0;
  let lastShotEnd = -Infinity;

  for (const [start, end] of sortedTargets) {
    const needsNewShot = start >= lastShotEnd;
    if (!needsNewShot) continue;
    interceptorCount++;
    lastShotEnd = end;
  }

  return interceptorCount;
}
```

## 15. Dry-run

`(1,4),(3,7),(5,12)` sorted như trên: shot đầu tại `4-ε` cover hai interval đầu vì `3<4`; interval ba có `5>=4`, cần shot mới tại `12-ε`. Answer 2.

## 16. Edge cases

1. Hai interval chỉ chạm endpoint: cần hai shot.
2. Một interval chứa toàn bộ interval khác.
3. Mọi interval overlap.
4. Mọi interval rời nhau.

## 17. Lỗi JavaScript thường gặp

- Sort theo start thay vì earliest end mà không có proof tương ứng.
- Dùng `start > lastEnd`, coi endpoint chạm là overlap.
- Chọn midpoint và mất khả năng cover interval sau.
- Mutate targets không chủ ý.

## 18. Bài transfer cùng pattern

- OF030: cùng earliest-finish interval greedy.
- OF028: greedy pairing hai cực trị, proof khác.
- OF025: greedy local conflict trên line.

Tín hiệu: chọn ít điểm nhất để stab interval ⇒ sort endpoint và đặt điểm muộn nhất còn hợp lệ.

### Loop and condition derivation

- **Nhịp lặp:** `quét từng [start, end] theo end không giảm.`. Đây là lý do code dùng block bắt đầu bởi `for (const [start, end] of sortedTargets) {`, thay vì chọn loop theo thói quen.
- **Câu hỏi trước branch:** “start có nằm trước boundary end của phát gần nhất không.”. Trong dry run `(1,4),(3,7),(5,12)`, đối chiếu dòng làm condition true và dòng làm condition false; code tương ứng bắt đầu tại `if (!needsNewShot) continue;`.
- **Tiến triển:** for...of tự sang target kế tiếp.. Nếu state/pointer không đổi, loop có thể xét lại cùng candidate hoặc giữ representation lệch current.
- **Thứ tự:** phải hoàn thành `tăng count và gán lastShotEnd = end chỉ khi cần phát mới.` ở scope sở hữu current rồi mới chuyển nhịp. Dòng movement chính là `for (const [start, end] of sortedTargets) {`.
- **Cleanup:** không cần lưu epsilon; end boundary cùng dấu strict biểu diễn đủ.. Nếu là “không cần”, state đã hoàn tất ngay trong main loop; nếu có, block chỉ chạy sau khi traversal đã cung cấp đủ thông tin.

**Kiểm tra theo family cho Hệ thống đánh chặn:** Condition của scan/simulation phải theo đúng tie-break và thứ tự rule của đề. So sánh strict hay non-strict chỉ đổi khi boundary/tie của bài chứng minh, không vì thói quen viết comparator.

### Complexity proof from movements

Time `O(n log n)` do sort, scan `O(n)`, space `O(n)` vì copy input.

**Proof từ operation của Hệ thống đánh chặn:** Tách chi phí chuẩn bị (nếu có sort) khỏi traversal. Trong traversal, mỗi item/candidate được xét đúng số lần mô tả bởi loop; không nhân các loop nối tiếp thành tích. Main loop được mô tả là `quét từng [start, end] theo end không giảm.`; movement là `for...of tự sang target kế tiếp.`. Vì vậy phải cộng chi phí các phase nối tiếp và chỉ nhân khi một phase thật sự chạy trọn bên trong mỗi lượt ngoài. Auxiliary space chính là state `lastShotEnd và interceptorCount.`, không tính output nếu convention của bài tách output.

#### 19. Problem → Code hoàn chỉnh

**Làm tay:** giống camera nhưng interval **mở**. Chọn target có end sớm nhất và bắn tại
`end-ε`. Target sau chỉ được cover nếu `start < end cũ`; chạm đúng endpoint (`start===end cũ`)
không cover nên cần phát mới.

```js
function minimumInterceptorsBruteForce(targets) {
  const scaledCandidates = targets.flatMap(([start, end]) => [start * 2 + 1, end * 2 - 1]);
  const candidates = [...new Set(scaledCandidates)];
  let best = Infinity;
  function choose(index, shots) {
    if (shots.length >= best) return;
    if (index === candidates.length) {
      const allCovered = targets.every(([start, end]) =>
        shots.some((shot) => start * 2 < shot && shot < end * 2),
      );
      if (allCovered) best = shots.length;
      return;
    }
    choose(index + 1, shots);
    shots.push(candidates[index]);
    choose(index + 1, shots);
    shots.pop();
  }
  choose(0, []);
  return best;
}
```
