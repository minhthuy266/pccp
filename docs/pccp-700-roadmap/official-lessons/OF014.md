# OF014 — Hai hàng đợi ưu tiên

- Nguồn đề: [Programmers lesson 42628](https://school.programmers.co.kr/learn/courses/30/lessons/42628?language=javascript)
- Pattern chính: min/max heap + lazy deletion
- Mức trong bank: TRANSFER / variant

## 01. Contract

Xử lý lệnh insert, delete maximum, delete minimum. Delete trên cấu trúc rỗng bị bỏ qua. Cuối trả `[max,min]`, hoặc `[0,0]` nếu rỗng. Duplicate value là các occurrence riêng.

## 02. Bound

Sort array sau mỗi command hoặc splice cực trị là tốn kém. Hai heap cho hai cực trị `O(log n)` nhưng phải đồng bộ deletion.

## 03. Brute force

Giữ array, insert push, delete sort rồi shift/pop. Đúng nhưng sort lặp `O(q² log q)` worst case.

## 04. Bottleneck

Xóa từ min heap không thể xóa occurrence tương ứng trong max heap nhanh. Gán unique id cho mỗi insert và đánh dấu alive; heap kia bỏ entry chết khi nó nổi lên root.

## 05. Pattern

Dual heap lazy deletion:

```text
insert same {value,id} into both heaps; alive[id]=true
delete one root after cleaning; alive[id]=false
clean(heap): pop while root id dead
```

## 06. State

MinHeap, MaxHeap, `alive[id]`, `liveCount`, `nextId`.

## 07. Transition

Insert tăng liveCount. Delete nếu liveCount>0: clean heap tương ứng, pop, mark dead, giảm count. Cuối clean cả hai trước peek.

## 08. Invariant

Mỗi live occurrence có một entry trong cả hai heap; `alive` là nguồn sự thật. Sau clean, root là cực trị trong tập live. Unique id giữ duplicate độc lập.

## 09. Complexity

Mỗi entry push hai lần và pop tối đa một lần khỏi mỗi heap: amortized `O(q log q)`, space `O(q)`.

## 10. Pseudocode

```text
for operation:
  insert: create id, push both, alive true
  delete if nonempty:
    choose heap; clean dead roots; pop; mark dead
if empty return [0,0]
clean both; return [maxRoot,minRoot]
```

## 11. Code bước 1 — dựng state

## 12. Code bước 2 — viết transition

```js
function clean(heap,alive) {
  while (heap.size && !alive[heap.peek().id]) heap.pop();
}
```

## 13. Code bước 3 — ghép vòng lặp

```js
const entry={value,id:nextId++};
alive[entry.id]=true; minHeap.push(entry); maxHeap.push(entry);
```

## 14. Code hoàn chỉnh

Code executable gồm heap đầy đủ: [solutions/official/OF014.js](../../../solutions/official/OF014.js).

```js
class NumericHeap {
  constructor(compare) {
    this.values = [];
    this.compare = compare;
  }
  get size() {
    return this.values.length;
  }
  peek() {
    return this.values[0];
  }
  push(value) {
    const heap = this.values;
    heap.push(value);
    let child = heap.length - 1;
    while (child > 0) {
      const parent = Math.floor((child - 1) / 2);
      if (this.compare(heap[parent], heap[child]) <= 0) {
        break;
      }
      [heap[parent], heap[child]] = [heap[child], heap[parent]];
      child = parent;
    }
  }
  pop() {
    const heap = this.values;
    if (heap.length === 0) {
      return undefined;
    }
    if (heap.length === 1) {
      return heap.pop();
    }
    const root = heap[0];
    heap[0] = heap.pop();
    let parent = 0;
    while (true) {
      const left = parent * 2 + 1;
      const right = left + 1;
      let best = parent;
      if (left < heap.length && this.compare(heap[left], heap[best]) < 0) {
        best = left;
      }
      if (right < heap.length && this.compare(heap[right], heap[best]) < 0) {
        best = right;
      }
      if (best === parent) {
        break;
      }
      [heap[parent], heap[best]] = [heap[best], heap[parent]];
      parent = best;
    }
    return root;
  }
}

function doublePriorityQueue(operations) {
  const minHeap = new NumericHeap((a, b) => a.value - b.value);
  const maxHeap = new NumericHeap((a, b) => b.value - a.value);
  const alive = [];
  let liveCount = 0;
  let nextId = 0;

  function clean(heap) {
    while (heap.size > 0 && !alive[heap.peek().id]) {
      heap.pop();
    }
  }

  for (const operation of operations) {
    const [command, rawValue] = operation.split(" ");
    const value = Number(rawValue);

    if (command === "I") {
      const entry = { value, id: nextId };
      nextId += 1;
      alive[entry.id] = true;
      minHeap.push(entry);
      maxHeap.push(entry);
      liveCount += 1;
      continue;
    }

    if (liveCount === 0) {
      continue;
    }
    const heap = value === 1 ? maxHeap : minHeap;
    clean(heap);
    const removed = heap.pop();
    alive[removed.id] = false;
    liveCount -= 1;
  }

  if (liveCount === 0) {
    return [0, 0];
  }
  clean(minHeap);
  clean(maxHeap);
  return [maxHeap.peek().value, minHeap.peek().value];
}
```

## 15. Dry-run

Insert 5 hai lần tạo id0,id1. Delete max mark chỉ một id dead, liveCount 1. Clean heap còn lại có thể pop dead id nhưng vẫn giữ occurrence 5 sống; kết quả `[5,5]`.

## 16. Edge cases

Delete empty; duplicate values; delete min rồi max; tất cả entries dead nhưng còn nằm vật lý trong heap.

## 17. Lỗi JavaScript thường gặp

Dùng value làm alive key làm mất duplicate; không clean trước delete/peek; giảm liveCount khi delete empty; comparator max sai dấu; heap pop empty.

## 18. Bài transfer cùng pattern

- OF012: một min-heap đủ.
- OF013: heap object với comparator nhiều key.
- OF009: priority domain nhỏ dùng count array.

Tín hiệu: cần đồng thời min/max và không có balanced tree sẵn ⇒ hai heap đồng bộ bằng id + lazy deletion.

## 19. Làm bằng tay và brute force executable

Insert 5 hai lần phải tạo hai occurrence khác nhau. Delete max chỉ xóa một occurrence; cấu trúc vẫn
còn `[5,5]` dưới dạng max/min. Nếu alive keyed bằng value, cả hai bản sao sẽ bị coi là đã chết.

```js
function doublePriorityQueueBrute(operations) {
  const values = [];

  for (const operation of operations) {
    const [command, rawValue] = operation.split(" ");
    const value = Number(rawValue);
    if (command === "I") {
      values.push(value);
      continue;
    }
    if (values.length === 0) continue;
    values.sort((a, b) => a - b);
    if (value === 1) values.pop();
    else values.shift();
  }

  if (values.length === 0) return [0, 0];
  values.sort((a, b) => a - b);
  return [values[values.length - 1], values[0]];
}
```

Brute force đúng nhưng sort lặp. Hai heap không xóa đồng bộ vật lý; `alive` đồng bộ logic.

## 20. Bảng state và khởi tạo

| State | Ý nghĩa | Khởi tạo |
| --- | --- | --- |
| `minHeap` | candidate minimum theo value tăng | rỗng |
| `maxHeap` | candidate maximum theo value giảm | rỗng |
| `alive[id]` | occurrence còn sống về logic | true khi insert |
| `nextId` | identity mới, kể cả duplicate value | `0` |
| `liveCount` | số occurrence sống | `0` |

## 21. Blueprint từ đề đến code

1. Một heap chỉ hỗ trợ nhanh một đầu; bài cần cả min và max.
2. Push cùng object `{value,id}` vào hai heap đối nghịch.
3. Xóa ở một heap bằng cách mark `alive[id]=false`, không tìm trong heap kia.
4. Trước pop hoặc final peek, clean liên tục các root đã chết.
5. Dùng `liveCount` để nhận biết logical empty dù heap vật lý còn entry.
6. Identity theo id, không theo value, để duplicate độc lập.

## 22. Invariant, lỗi lộ diện và recall

Mỗi occurrence sống có một entry trong cả hai heap; `alive` là nguồn sự thật duy nhất. `clean(heap)`
không cần xóa dead entry nằm sâu vì nó chưa ảnh hưởng cực trị. Sau clean, root là cực trị trong tập
sống. Mỗi stale entry bị pop nhiều nhất một lần nên lazy deletion vẫn amortized `O(log q)`.

| Sai lầm | Test làm lộ | Kết quả đúng |
| --- | --- | --- |
| alive keyed bằng value | `I 5, I 5, D 1` | `[5,5]` |
| không clean trước final peek | xóa min rồi còn stale root bên max | cực trị live |
| giảm count khi delete empty | `D -1, I 3` | `[3,3]` |
| max comparator cùng chiều min | `I 1, I 9, D 1` | `[1,1]` |

Recall: **cần hai cực trị ⇒ dual heap; cùng id ở hai heap; delete logic bằng alive, clean khi root lộ ra.**

## A17. Blueprint đủ trường và Recall ba tầng

```text
OUTPUT: [maximum, minimum] còn sống sau toàn bộ operations, hoặc [0,0].
PREPARE: tạo minHeap/maxHeap dùng chung object id và mảng alive.
GLOBAL STATE: two heaps, alive flags, nextId và liveCount.
INIT: heaps rỗng; alive rỗng; nextId=0; liveCount=0.
MAIN LOOP: parse từng operation theo input order.
CURRENT ITEM: command/value; khi clean là root entry của heap.
PER-ITERATION STATE: entry {value,id} và deletedEntry.
CHECK: insert hay delete; liveCount > 0; root id còn alive không.
BRANCH: insert push hai heap; D 1 pop max; D -1 pop min; delete empty thì bỏ qua.
UPDATE: insert đánh alive true và tăng liveCount; delete đánh false và giảm count.
POINTER MOVEMENT: operation loop tiến; clean pop liên tục stale roots.
STOP / RETURN: sau mọi operation clean hai root; liveCount 0 trả [0,0], khác trả hai value.
CLEANUP: lazy-clean cả min và max trước final peek để loại entry chết.
```

- Recall 1: Mỗi occurrence có id riêng trong hai heap; xóa chỉ mark dead, root stale mới bị clean.
- Recall 2: STATE min/max/alive/liveCount → LOOP ops → CHECK command/live → UPDATE mark → CLEANUP roots → RETURN.
- Recall 3: Điền `alive[entry.id] = ___` khi insert và `alive[deleted.id] = ___` khi delete.
